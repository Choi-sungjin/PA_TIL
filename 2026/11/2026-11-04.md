# 2026-11-04 TIL — INT8 양자화: 눈금 간격과 캘리브레이션 세트, Q/DQ, 그리고 TensorRT 10·11 명령 분기

> 강의 자료로 정리. 어제는 FP16·INT8을 "왜 검토하는가"까지 봤고, 오늘은 INT8이 **실제로 숫자를 어떻게 줄이는지**와 **그 결과를 어떻게 믿을지**를 배웠다. 양자화는 파일을 작게 만드는 작업이 아니라 **눈금 간격을 정하는 일**이었고, 잘 됐는지는 속도가 아니라 과제 지표로 판정한다.

---

## 1. 양자화는 눈금을 새로 긋는 일이다

실수를 8비트 정수로 바꿨다가 복원하는 식은 이렇다.

```
q  = clip( round(x / s) + z , -128, 127 )     # 실수 x → 정수 q
x̂ = s · (q − z)                               # 정수 q → 복원값
```

- `s`는 scale(눈금 간격), `z`는 zero point다. INT8이면 q가 −128~127, 256칸뿐이다.
- 복원값 x̂는 원래 x가 아니라 **가장 가까운 눈금으로 반올림한 값**이다. 눈금 간격이 넓을수록 오차가 커진다(오차는 최대 s/2).
- 대칭 양자화 예: `z = 0`, `s = (절댓값 최대) / 127`.

강의의 예를 직접 계산해 봤다. 값 대부분이 ±0.1 안인데 이상치 하나가 10이라면:

- `s = 10 / 127 ≈ 0.0787`
- 절댓값이 **0.0394 미만인 값은 전부 q = 0**이 되어 서로 구분이 안 된다.
- 0.1은 q = 1이 되어 0.0787로 복원된다. 값의 약 21 %가 틀어진다.

이상치 하나가 범위를 잡아 먹어서 **대부분의 값이 쓸 수 있는 눈금이 몇 칸 안 남는** 셈이다. 그래서 범위를 정하는 선택이 곧 정확도의 선택이다.

- 범위를 이상치까지 넓힌다 → 이상치는 살지만 작은 차이를 구분 못 한다.
- 범위를 클리핑해서 좁힌다 → 중심부 해상도는 좋아지지만 이상치가 잘려 나간다.
- 가중치와 activation은 값의 범위가 달라서 scale을 따로 잡는다. 채널별로 잡을지 텐서별로 잡을지도 설정 항목이다.

내 이해로는, 가중치는 학습이 끝나 값이 고정이라 파일만 보고 범위를 알 수 있지만 activation은 입력에 따라 달라서 **대표 데이터를 실제로 흘려 봐야** 범위를 안다. 다음 절의 캘리브레이션이 필요한 이유가 이것이다.

## 2. 캘리브레이션 세트는 현장을 대표해야 한다

activation의 범위를 재는 데이터가 scale을 정하므로, 이 데이터가 현장과 다르면 눈금이 엉뚱하게 그어진다. 강의에서 가장 강조한 말은 **수량을 늘리기 전에 빠진 상황부터 채우라**는 것이었다.

채워야 할 축은 이렇게 정리했다.

- **물체**: 색(빨강·초록)과 모양(직육면체·원기둥). 드문 클래스를 빠뜨리지 않는다.
- **자세**: 서 있음, 누워 있음, 일부 가림.
- **빛**: 밝음, 어두움, 아크릴 반사.
- **거리**: 크게 보이는 경우와 작게 보이는 경우.

지켜야 할 규칙:

- 300~500장은 실습을 시작하는 숫자일 뿐이고, 정확도를 보장하는 정답이 아니다.
- calibration / validation / test를 나눈다. **같은 장면의 연속 프레임이 서로 다른 쪽에 들어가면 누수**다. 10/29에 val 1000장 중 818장이 train에 있던 장면이었던 것과 같은 종류다.
- INT8 설정을 고르는 일은 validation으로 한다. **test는 최종 평가에만** 쓰고, test 결과를 보면서 반복 튜닝하면 test를 소모한 것이다.
- 캘리브레이션 입력의 해상도와 전처리는 실제 추론과 똑같아야 한다. 어제 정리한 입출력 계약이 여기에도 걸린다.
- 합성 데이터로만 캘리브레이션했다면 실제 카메라에서의 정확도는 따로 검증한다. 실제 카메라 분포는 나중에 추가한다.

## 3. Q/DQ로 양자화를 그래프에 적어 둔다

Q/DQ는 "어디서 어떤 scale로 양자화되는가"를 **그래프 안에 명시**하는 방식이다.

- **QuantizeLinear (Q)**: 실수 텐서를 scale 기준으로 정수로 바꾼다. scale·zero point·dtype을 점검한다.
- **DequantizeLinear (DQ)**: 양자화된 값을 계산용 실수로 되돌려 표현한다. 짝이 되는 Q의 scale과 맞는지 본다.
- 연산 앞뒤에 이 쌍을 끼워 두면, TensorRT 빌더가 지원되는 패턴을 찾아 낮은 정밀도 커널로 최적화한다.

여기서 제일 중요한 문장은 이거였다. **INT8 파일을 만들었다고 전체 그래프가 INT8 커널로 실행되는 것은 아니다.** 지원되지 않는 패턴은 높은 정밀도로 남거나 fallback된다. 그래서 빌드 후에 **레이어별 실제 dtype**을 확인하고, 마지막에는 양자화 오차를 mAP, 중심 오차, 정책 성공률 같은 과제 지표로 판단한다.

- TensorRT 11에서는 implicit calibration 경로가 제거되어서, Q/DQ 모델 같은 명시적 경로를 쓴다.
- 배포 GPU가 지원하지 않는 FP8/FP4 예제를 Nano의 INT8 실습에 그대로 가져다 쓰지 않는다.

## 4. TensorRT 10.x와 11.x 명령은 섞지 않는다

어제 "다음에 할 것"에 적어 둔 10/11 분기가 이 부분이었다.

| 하려는 것 | 10.x | 11.x |
|---|---|---|
| FP16 | `--fp16` 플래그 | 모델 안에 dtype/Cast로 표현한 뒤 빌드 |
| INT8 | 기존 calibrator 또는 Q/DQ | Q/DQ 모델을 빌드 |
| 민감한 층 | precision을 지정하는 경로 | 그래프에 dtype으로 표현 |
| 전달 비용 측정 | 포함 옵션을 확인 | 기본은 제외, `includeDataTransfers`로 포함 |
| 첫 명령 | `trtexec --help` | `trtexec --help` |

- 11은 precision 플래그와 implicit calibration API를 없앴다. 그래서 같은 목적이어도 명령이 다르다.
- 명령을 외우지 말고, **설치된 TensorRT의 정확한 버전을 환경 기록에 확정**한 뒤 그 버전의 `--help`부터 읽는다.
- 최신 11 문서를 봤다고 10 환경을 무조건 바꾸지 않는다.
- 11은 CUDA Graph, spin wait, 전달 비용 같은 기본값도 바뀌었다. 10과 11을 비교할 때는 이 기본값 차이도 비교 조건에 넣는다.

## 5. 속도와 정확도를 함께 정해야 채택한다

강의의 교육용 예시(Jetson 실측이 아니다)를 따라 계산하면 이렇다.

- mAP가 0.90에서 0.886으로 떨어지면 **1.4 %p 하락**이다. 상대 감소율로 말하면 약 1.6 %라서, 두 말을 섞으면 안 된다.
- 허용선을 1.0 %p로 잡았다면 이 INT8은 지연이 더 좋아도 **바로 채택할 수 없다.**
- 지연만 보지 않는다. 허용 정확도, 오검출의 비용, 중심 오차를 함께 본다.

INT8이 허용선을 못 넘을 때 비교할 선택지는 세 가지다.

1. 캘리브레이션 데이터를 보완한다 (2절의 빠진 상황 채우기).
2. 민감한 층은 INT8에서 뺀다.
3. FP16으로 되돌린다.

허용선은 **측정하기 전에** 정해야 한다. 결과를 본 뒤에 허용선을 정하면 어떤 숫자도 통과시킬 수 있다.

## 6. 모델마다 판정 지표가 다르다

| 모델 | 꼭 볼 지표 | 추가로 볼 것 |
|---|---|---|
| YOLO | mAP50-95, 클래스별 recall | 작은 물체, 가림, 오검출 |
| BC 정책 | 성공률, 행동 오차 | 접촉 직전의 미세한 행동 |
| Diffusion 정책 | 성공률, K-step 전체 지연 | seed와 denoise step 고정 |
| 퍽 CenterPose | 중심 오차(mm), 축/대칭 오차 | 유효 출력 비율 |
| AprilTag | ID recall, 오ID, 위치 오차 | 검출기가 DNN 양자화 대상인지 먼저 구분 |

- 양자화는 **평가 조건을 고정한 실험**으로 판단한다. 같은 입력, 같은 후처리, 같은 test 세트로 FP32 · FP16 · INT8을 나란히 놓고 본다.
- Diffusion은 seed와 denoise step을 고정하지 않으면 정밀도 차이인지 샘플링 차이인지 구분이 안 된다.
- BC·Diffusion 체크포인트가 없으면 결과를 만들어 채우지 말고 **"미실행"으로 표시**한다.
- AprilTag는 양자화가 영향을 주는 부분이 DNN뿐이라면, 어디까지가 DNN인지 먼저 가르라는 뜻으로 읽었다(내 해석).
- 같은 태그를 여섯 면에 붙이면 태그 ID만으로는 어느 면인지 방향을 정할 수 없다. 퍽에 태그를 붙일 때 모호성이 생긴다.

# 오늘 내용을 한 줄로 이으면

```
대표 데이터로 activation 범위를 잰다 (캘리브레이션) → scale / zero point 결정
  → Q/DQ로 그래프에 명시
  → 설치된 TensorRT 버전에 맞는 명령으로 엔진 빌드
  → 레이어별 실제 dtype과 fallback 확인
  → validation으로 INT8 설정 선택
  → test로 한 번 최종 판정 (과제 지표 + 지연, 허용선은 미리 정해 둠)
  → 허용선 안이면 채택, 아니면 데이터 보완 / 민감 층 제외 / FP16 롤백
```

## 헷갈리기 쉬운 지점 / 메모

- **%p와 %는 다르다.** 0.90 → 0.886은 1.4 %p 하락이고 상대로는 약 1.6 %다. 허용선이 어느 쪽 기준인지 먼저 확인한다.
- **INT8 파일 ≠ INT8 실행.** 파일이 INT8이어도 실제로 도는 커널의 dtype은 따로 봐야 한다.
- **캘리브레이션 장수 ≠ 정확도 보장.** 300~500장은 시작점이고, 중요한 건 빠진 상황이 없는 것이다.
- **test를 보면서 튜닝하면 test가 아니다.** 설정 선택은 validation, test는 마지막에 한 번.
- **최신 문서가 내 환경의 정답은 아니다.** 설치된 버전 문서를 기준으로 읽는다.
- 이번 내용은 강의 자료로 정리한 것이고, 위 계산은 개념 설명용 예시다. 아직 내 Jetson에서 INT8을 돌려 본 값이 아니다.

## 오늘의 한 줄

> INT8은 256개 눈금으로 값을 읽는 일이라 눈금을 어디까지 넓게 긋느냐가 정확도를 정한다. 그 선택이 맞았는지는 속도가 아니라, 허용선을 미리 정해 둔 같은 test 세트의 과제 지표로만 판정한다.
