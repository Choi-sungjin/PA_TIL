# 2026-11-11 TIL — 상태머신의 상태를 음성으로 읽어 주니, 화면을 안 봐도 로봇이 지금 뭘 하는지 들렸다

> 오늘은 로봇에 음성 모델 API를 붙였다. 목표는 두 가지였다. 플래닝 상태머신이 내보내는 상태를 구독해서 **지금 로봇이 어떤 상태인지 말로 알려 주는 것**, 그리고 "크래프트"라고 부르면 **현재 상태를 보고 대답하는 것**. 실제로 주행하는 동안 "목표 지점 이동 시작할게!", "길이 막혀서 잠깐 기다리는 중이야." 같은 말이 나와서, 노트북 화면이나 RViz를 보지 않고도 상태를 알 수 있었다. 그런데 처음에는 로그에 "재생했다"고 찍히는데 소리가 하나도 안 났다. 그 원인을 찾는 게 오늘의 절반이었다.

---

## 1. 구조: 상태머신을 듣는 노드, 말하는 노드

음성 노드(`voice_node`)는 ROS 2 노드 하나이고, 상태를 만들지 않고 **듣기만** 한다.

| 방향 | 토픽 | 용도 |
|---|---|---|
| 구독 | `/planning/state` | 상태머신의 현재 상태 (`Ready`, `Run.Execute`, `Run.Complete`, `Run.Stopping`, `Fault` 등) |
| 구독 | 플래닝 diagnostics, 제어 상태 | 막힘·실패 이유, 제어기 준비 여부 |
| 구독 | `/voice/say`, `/voice/ask` | 지정한 문장을 말하기 / 질문에 답하기 |
| 발행 | `/voice/utterance`, `/voice/heard`, `/voice/speaking` | 말한 문장, 들은 질문, 지금 말하는 중인지 |

말하는 방식을 둘로 나눴다.

- **상태가 바뀌었을 때**: GPT를 거치지 않고 **미리 정해 둔 문장**을 바로 말한다. `Run.Execute`가 오면 "목표 지점 이동 시작할게!", `Ready`가 오면 "준비 끝! 출발 신호 기다리는 중이야." 상태 변화는 즉시 들려야 하고, 매번 GPT에 물으면 1~2초가 늦기 때문이다.
- **불렸을 때**: "크래프트, 왜 멈췄어?" 같은 질문은 GPT에 **현재 상태를 같이 넘겨서** 대답하게 한다. 상태를 모르는 채로 답하면 그럴듯한 거짓말이 나오기 때문에, 질문 앞에 상태머신 상태와 경과 시간을 붙인다.

## 2. 고정 문장은 미리 합성해서 저장해 둔다

상태가 바뀔 때 말할 문장은 종류가 정해져 있다. 상태 × 단계 이름, 그리고 실패 이유별 문장을 전부 세어 보니 **73개**였다. 이걸 한 번에 음성으로 합성해서 파일로 저장해 두고(캐시), 상태가 오면 파일을 바로 재생한다.

- 캐시 키는 `모델 | 목소리 | 말투 지시 | 속도 | 문장`을 해시한 값이다. 목소리나 말투 지시를 바꾸면 키가 달라져서 옛 목소리가 섞이지 않는다.
- 합성 모델은 `gpt-realtime-2.1`, 목소리는 `marin`, 말투는 "귀엽고 발랄한 로봇 친구, 오류와 멈춤은 차분하게"로 정했다. 73개 모두 실패 없이 끝났다.
- 저장해 둔 문장은 **네트워크가 끊겨도** 나온다. 반대로 GPT가 새로 쓴 문장은 말하는 순간에 합성해야 한다.
- 질문을 받자마자 "어디 보자!", "짜스!" 같은 짧은 반응은 이 캐시에서 바로 틀어서 **대답을 기다리는 1~2초의 빈 시간을 메운다.**

## 3. 호출어는 소리 크기로 구간을 자르고, 글자로 확인한다

마이크는 `pw-record`로 16 kHz 모노를 받는다. 말하는 구간은 **배경 소음 크기보다 큰 소리**가 이어지는 동안으로 자른다(이 로봇에는 webrtcvad가 없어서 크기 기준만 쓴다). 잘라낸 구간을 음성 인식에 보내고, 나온 글자에서 호출어를 찾는다.

- 호출어는 "크래프트". 인식이 "크래프트야", "크래프트." 처럼 조금 달라져도 잡도록 글자 차이를 2자까지 허용한다.
- 이름 없이 말한 건 무시한다(오늘 시험에서 이름 없는 말은 전부 무시됐다).
- 대답한 뒤 6초 안에 이어서 말하면 **이름 없이도** 이어 묻기로 받는다. 대화 중에 매번 이름을 부르는 건 불편해서다.
- 로봇이 말하는 소리를 마이크가 다시 듣고 자기 말에 반응하면 안 된다. 마이크는 계속 열어 두되, 로봇이 말하는 동안과 말이 끝난 직후에 들어온 소리는 버린다.

## 4. PC에서 실제 API로 시험한 결과

녹음해 둔 목소리를 가짜 마이크로 흘려 넣고, 가짜 상태 시나리오(`Run.Execute` 도중 "path blocked; waiting before replanning")를 돌렸다. 말은 소리 대신 파일로 받았다.

| 입력 | 결과 | 시간 |
|---|---|---|
| "크래프트" (이름만) | "짜스!" 후 현재 상태 말하기 | 음성 인식 0.82 s |
| "크래프트야, 왜 멈췄어?" | "길이 막혀서 잠깐 기다리는 중이야, 8초째인 것 같아." | 인식 0.67~0.74 s, GPT 1.3~2.2 s |
| 이어서 "그럼 얼마나 기다려야 돼?" | "…지금으로선 얼마나 걸릴지 모르겠어." (모르는 걸 모른다고 말함) | 인식 1.08 s, GPT 1.4 s |
| 이어서 "오늘 점심 뭐 먹을까?" | "모르겠어, 지금은 길이 막혀서 잠깐 기다리는 중이야" | 인식 1.09 s, GPT 1.3 s |
| 이름 없는 말 | 무시 | - |

- 두 번째 대답에 "8초째"가 들어간 건 상태에 **경과 시간**을 같이 넘겼기 때문이다. 말투는 GPT가 만들지만 사실은 상태머신이 준 값이다.
- 엉뚱한 질문에도 지금 상태로 되돌아오는 게 좋았다. 로봇이 점심 메뉴를 추천하기 시작하면 곤란하다.
- 문장이 재생되기 시작하기까지는 한 번 재 봤을 때 2.78 s(합성 3.90 s, 소리 길이 4.6 s)였다. 소리가 다 만들어지기 전에 도착하는 대로 재생하는 스트리밍 덕에 합성 시간보다 일찍 시작한다. 한 번만 잰 값이라 평균은 아니다.
- 단위 테스트는 195개 통과, 3개는 건너뜀(SDK가 필요한 테스트).

## 5. 로봇에 올렸더니: 재생 성공이라고 찍혔는데 소리가 없었다

젯슨에 코드와 합성 캐시를 복사하고 사용자 서비스(systemd)로 등록해서 부팅 때 자동으로 뜨게 했다. 주행을 돌렸더니 로그에는 상태 문장이 20번 넘게 "말했다"고 찍혔는데, 현장에서는 아무 소리도 안 들렸다. "크래프트"를 불러도 답이 없었다.

로그에서 찾은 것:

- `/planning/state` 구독자에 음성 노드가 잡혀 있었다. **구독은 정상이었다.**
- 재생은 내장 아날로그 출력으로 나갔는데, 그 출력에는 **스피커가 연결돼 있지 않았다.** 재생 명령이 오류 없이 끝나면 로그는 성공으로 찍힌다. 소리가 나는지는 로그가 말해 주지 않는다.
- 마이크도 내장 아날로그 입력이었고, 3초 녹음해 보니 **표본이 전부 0**(rms 0)이었다. 들을 수 없는 마이크로 호출어를 기다리고 있던 것이다.
- 이 로봇의 스피커·마이크는 둘 다 블루투스 스피커 F25였다. 연결은 돼 있는데 소리 장치로 안 잡혔다. 로그인 화면(gdm) 사용자의 WirePlumber가 부팅 때 블루투스 오디오를 먼저 차지해서, 내 계정 쪽은 `RegisterProfile() failed: NotPermitted`로 거부당하고 있었다.

고친 방법:

```bash
# gdm 쪽 WirePlumber의 블루투스를 끈다 (sudo 필요)
sudo -u gdm mkdir -p /var/lib/gdm3/.config/wireplumber/bluetooth.lua.d
echo 'bluez_monitor.enabled = false' | sudo -u gdm tee /var/lib/gdm3/.config/wireplumber/bluetooth.lua.d/60-no-bluetooth.lua
sudo pkill -u gdm wireplumber

# 내 계정에서 다시 붙인다
systemctl --user restart wireplumber
bluetoothctl disconnect <F25 주소> && bluetoothctl connect <F25 주소>
wpctl status        # Sinks/Sources에 F25가 * 로 잡히는지
```

그 뒤에는 F25가 기본 출력·입력으로 잡혔고, 마이크 4초 녹음이 rms 448, 최대 22011로 **신호가 들어왔다.** 그 상태에서 주행하니 상태 문장이 스피커로 나왔다.

## 7. 막혔던 지점 / 메모

- **"재생했다"와 "소리가 났다"는 다르다.** 재생 명령의 종료 코드는 출력 장치가 어디로 연결돼 있는지 모른다. 10/30에 "명령대로 돌았다"와 "로봇이 움직였다"가 달랐던 것과 같은 종류의 문제였다. 소리는 장치가 어디로 잡혔는지(`wpctl status`)와 입력 신호 크기로 확인한다.
- **마이크는 켜져 있다고 듣는 게 아니다.** 입력 신호가 전부 0이어도 노드는 "마이크 켜짐"이라고 한다. 기동할 때 몇 초 녹음해서 크기를 확인해 두는 편이 낫겠다.
- **투어처럼 구간이 짧은 주행에서는 같은 문장이 7~10초마다 반복된다.** "작업 시작할게!", "목표 지점 이동 끝났어!"가 번갈아 나왔다. 같은 알림 사이 최소 간격(`state_cooldown_s`, 지금 8초)을 늘리거나 알릴 상태를 줄여야 한다.
- 상태 토픽이 한동안 안 오면 "어? 상태 신호가 끊겼어.", 다시 오면 "상태 신호 다시 들어온다!"라고 말한다. 플래닝이 꺼진 건지 음성 노드가 못 듣는 건지 귀로도 구분할 수 있어서 의외로 유용했다.
- 블루투스 스피커를 헤드셋 방식(HFP)으로 잡으면 마이크는 쓸 수 있지만 재생이 전화 음질(16 kHz)이 된다. 음질이 거슬리면 마이크만 USB로 따로 다는 쪽을 생각해 본다.
- 합성 모델 이름은 계속 바뀌고 일부 모델은 종료 예고가 나 있어서, 모델명은 설정 파일 한 곳에서만 바꾸게 해 두었다.

## 오늘의 한 줄

> 상태머신이 내보내는 상태를 로봇이 말로 읽어 주니 화면 없이도 지금 무슨 상태인지 알 수 있었다. 다만 "말했다"는 로그를 믿지 말고, 소리가 나가는 장치와 들어오는 마이크 신호를 직접 확인해야 한다.
