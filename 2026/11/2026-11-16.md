# 2026-11-16 TIL — 프로젝트 3: 자율주행과 퍽 5개 적재까지 성공했고, 전체 미션은 끝내지 못했지만 2등을 수상했다

> 오늘은 프로젝트 3 퍽 운반 미션을 수행했다. 자율주행을 완료했고, 그리퍼로 퍽 5개를 집어 적재하는 데까지 성공했다. 하지만 그 이후 과정에서 실패해 전체 미션을 끝까지 마치지는 못했다. 최종 결과는 **2등 수상**이었다. 주행과 적재가 실제로 이어진 성과도 있었고, 남은 단계를 끝까지 연결해야 한다는 과제도 남았다.

## 1. 오늘의 결과

| 항목 | 결과 |
|---|---|
| 자율주행 | 완료 |
| 퍽 집기·적재 | 그리퍼로 **5개 적재 완료** |
| 적재 이후 과정 | 실패, 전체 미션 미완료 |
| 최종 성적 | **2등 수상** |

오늘의 성공 범위는 자율주행과 퍽 5개 적재까지다. 적재 이후에 실패했으므로 배달·배치·확인·복귀까지 모두 성공했다고 적을 수는 없다. 수상 결과와 미션 완주 여부도 따로 남긴다.

## 2. 시스템 구조: 보고, 순서를 정하고, 움직인다

발표 자료인 「CRAFT 시스템 노드 지도」를 기준으로 전체 흐름을 정리했다. 로봇 안의 프로그램은 역할을 나눠 맡고, 각 단계의 결과를 다음 단계로 넘긴다.

| 구성 | 맡은 일 |
|---|---|
| 센서 | 앞뒤 라이다와 위쪽·그리퍼 카메라로 주변과 퍽을 관측 |
| `perception_master` | 센서 정보를 정리하고 신호등·바코드·퍽 정보를 제공 |
| `mission_master` | 신호 확인부터 수집·배달·복귀까지 한 판의 순서를 관리 |
| `planning_master` | 목표까지의 경로, 상자 접근과 이탈, 작업 단계를 계획 |
| `control_master` | 주행과 팔·그리퍼 명령을 실행하고 결과를 반환 |
| 제어 보드 2대 | 바퀴·회전판과 팔·그리퍼 모터를 구동하고 상태를 되돌려 줌 |

미션은 **무엇을 할지**, 계획은 **어떻게 갈지와 어떤 순서로 움직일지**, 제어는 **명령대로 움직였는지**를 맡는다. 명령이 아래로 내려가는 것만큼 실행 결과가 다시 올라오는 것도 중요하다.

## 3. 자율주행: 위치를 알고, 길을 찾고, 경로를 따라간다

주행 구조는 세 부분으로 나눠 이해했다.

1. **현재 위치 추정**: 앞뒤 라이다 스캔을 로봇 기준으로 합친다. 바퀴 이동량과 관성 센서로 짧은 움직임을 이어 가고, 저장 지도와 스캔을 맞춰 지도 위 위치를 잡는다.
2. **경로 계획**: 지도에서 차체가 벽에 닿지 않을 여유를 확보한 뒤 길을 찾는다. 찾은 길은 불필요한 꺾임을 줄이고, 굽은 정도에 맞춰 속도를 정한다.
3. **경로 추종과 접근**: 경로 위의 앞쪽 지점을 따라가며 전진·회전을 조절한다. 상자 근처에서는 접근과 정렬을 거쳐 다음 작업으로 넘긴다.

경로를 만들었다는 것과 로봇이 실제로 도착했다는 것은 다르다. 오늘은 계획 설명에 그치지 않고 **실제 미션에서 자율주행을 완료했다**는 점이 성과였다.

## 4. 퍽 운반: 집기와 적재도 여러 단계가 이어진 작업이다

자료의 수집 구조는 **상자로 이동 → 퍽 관측 → 집을 퍽 선택 → 팔 접근 → 그리퍼로 잡기 → 들어 올리기 → 회전판에 적재**로 이어진다.

- 위쪽 카메라와 그리퍼 카메라는 퍽을 고르고, 가까이에서 중심과 방향을 확인하는 역할을 나눠 맡는다.
- 팔은 미리 가르친 자세를 바탕으로 접근하고, 카메라 관측으로 위치와 방향을 보정한다.
- 그리퍼가 닫혔다는 명령만으로 끝내지 않고, 모터 전류를 이용한 잡힘 신호를 확인하는 구조다.
- 집기 결과가 미션 쪽으로 돌아와야 다음 퍽 수집이나 다음 작업으로 넘어갈 수 있다.

오늘은 이 과정에서 **퍽 5개의 적재까지 성공했다.** 다만 수집 이후에는 운반 위치 배정, 배달, 배치 확인, 복귀 같은 단계가 남는다. 다섯 개를 실었다는 성과와 전체 퍽 운반 미션의 완료는 구분해야 한다.

## 5. 실패에서 남긴 점: 적재 다음 연결을 봐야 한다

이번에 확인된 결과는 **5개 적재 뒤 이후 과정에서 실패했다**는 것이다. 정확히 어느 단계에서 어떤 이유로 실패했는지는 아직 정리하지 못했으므로, 위치 오차나 인식·그리퍼 문제 중 하나로 단정하지 않는다.

다음에는 실패 직전과 직후를 같은 시간 기준으로 맞춰 봐야겠다.

- 미션이 어떤 단계에 있었고, 다음 단계로 넘어갈 조건은 무엇이었는지
- 계획 쪽이 작업 완료를 보냈는지, 실패나 대기 상태를 보냈는지
- 제어 쪽의 실제 작업 결과와 퍽 적재 상태가 일치했는지

시스템에는 계획의 생존 신호가 0.5초 동안 끊기면 제어가 멈추는 장치도 있다. 이런 정지 조건은 원인을 찾을 때 확인할 항목이지, 오늘의 실패 원인으로 확인된 것은 아니다.
