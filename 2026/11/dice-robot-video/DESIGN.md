# DESIGN — 주사위 기억 로봇 모션그래픽 (1920×1080, 30 fps)

사실 출처는 `FACTS.md` 하나. 맵 좌표·벽·경로 탐색은 `ref/dice_robot_reference.html` 의 값/로직을 `plan.js` 로 그대로 옮겨 재사용(수치 변경 없음).

## 1. 색 (이름 붙인 6개 + 과제 의미색)
| 이름 | hex | 역할 |
|---|---|---|
| Midnight | `#0B1118` | 배경(어두운 청흑) |
| Panel | `#141D27` (+ line `#2B3947`) | 카드·패널 면과 테두리 |
| Paper | `#E8EDF3` (muted `#8B97A4`) | 본문/제목 글자, 보조 글자 |
| Signal Blue | `#6FA8FF` | 주 강조: 챕터 칩, 진행 바, 경로선, L1~L3, 전환 라인 |
| Scan Violet | `#B592EA` | 로봇 카메라(시야·관측) 관련 요소 |
| Lamp R / Y / G | `#EF5A4F` / `#F0BC35` / `#3DB671` | 신호·퍽·그룹 색(과제 의미색, ref HTML 다크 팔레트와 동일) |

보조: 점수 항목 막대는 파랑~보라~청록 계열 8단계(채점 장면 한정).

## 2. 서체
- **Noto Sans KR** (npm @fontsource, `fonts/` 로컬 woff2, 500/700/900) — 한글 본문·제목. 키네틱 제목은 900.
- **JetBrains Mono** (시스템 설치본) — 숫자, 코드(P2-01), 좌표, 타이머, 칩 글자.
- 크기 기준: 키네틱 제목 110~150 px / 카드 제목 32~40 / 본문 22~28 / 자막 40(2줄 초과 시 34).

## 3. 레이아웃 (공통 프레임)
```
┌──────────────────────────────────────────────────────────────┐
│ [NN 챕터명]                         [공개 연습 문제 Q1 · P2-01 · 오름차순] │ y 36~84  (HUD, 카메라 영향 없음)
│                                                              │
│   콘텐츠 영역  y 105 ~ 875  (카메라 줌/팬은 이 층에만 적용)        │
│   좌: 맵/로봇/램프  ·  우: 카드/표/카운터                        │
│                                                              │
│      ┌──────────── 자막(text 필드, 문장 단위) ────────────┐        │ y ~890~1034
│      └────────────────────────────────────────────────────┘        │
│ ▬▬▬▬▬▬▬▬▬▬●────────────────────────────  (전체 진행 바)  │ y 1066~1072, 장면 경계 눈금
└──────────────────────────────────────────────────────────────┘
```
장면별 구도 (공식 발제 v5 기준, 로봇 사양 없음 — 로봇은 카메라+집게의 단순 아이콘):
1 인트로(좌 키네틱 제목·3칩, 우 맵) / 2 배치·퍽(좌 맵+L1~L3 ID 라벨, 우 고정 조건 카드 + R/G/Y 범례) / 3 ① 바코드(좌 출발구역 확대 맵, 우 바코드·4종 규칙 표) /
4 ② 점멸(좌 램프, 우 파형·상태, 하단 12칸 타임라인) / 5 ③④ 횟수 계산·유효성·오름차순 정렬·L1~L3 배정 / 6 ⑤ 전체 할당 계획(발제 예 R5 Y3 G4 → Q1 예제 배정) /
7 ⑥ 집기·이동·놓기(추적 카메라 맵, 왕복 3번 + 타임랩스 배지, 우 n/12 카운터) / 8 ⑥ 주사위 눈 배치(3×3 격자 클로즈업, ±10 mm, 2초 안정, 규칙 체크리스트) /
9 ⑦⑧ 재검증(새 관측 기록표, 복사 로그 불인정) + 복귀 3초 정지 / 10 채점 100점 / 11 오류·종료 + 8단계 아웃트로.

## 4. 모션 규칙
- 등장: 스프링(감쇠 오버슈트 `1−e^(−7u)cos(15u)`) 또는 ease-out(cubic/quintic). 키네틱 제목은 글자별 낙하+오버슈트(stagger 0.045~0.06 s).
- 강조: `pulse()` 링/글로우, 퍽 착지 펄스, 카운트업(ease-out cubic).
- 카메라: 장면마다 `camAt()` 키프레임(줌 1.0~1.3, 초점 이동). 맵 장면(6, 9)은 월드 좌표 자체를 줌/팬(장면 6 은 로봇 추적, 장면 9 는 마지막에 출발 구역 줌인).
- 진행 바: 하단 전체 진행 + 장면 경계 눈금.

## 5. 장면 전환 (경계 시각부터 0.60 s, ease in-out)
| 전환 | 방식 |
|---|---|
| 1→2, 5→6, 9→10 | 사선 와이프(폭 260 px, 파란 엣지 26 px) — 이전 장면은 1.08배 줌+암전 50% |
| 2→3, 6→7, 10→11 | 아이리스(화면 중심 원 반경 0→1250 px, 파란 링) |
| 3→4, 7→8 | 8분할 블라인드(분할 지연 0.12) |
| 4→5, 8→9 | 아래에서 위로 푸시(`easeOut5`, 파란 라인) |
마지막 0.9 s 는 전체 페이드 아웃.

## 6. 타이밍 구조
- `script.json`: `[{id, scene, text(자막), tts(읽기용), visual, at?, min_dur?}]`. 한 장면에 엔트리가 여럿일 수 있음(장면 4: s04a/b/c, 장면 9: s09a/b, 장면 11: s11a/b).
- `timing.json`: `{id: 초}` = 음성 길이 + 0.6 s 여유(앞 0.3 + 뒤 0.3). 지금은 `len(tts)/7.5 + 0.6` 추정치. 실제 음성 후에는 `python3 make_timing.py --audio` (SPEED=1.15 반영).
- `schedule.js`: 엔트리 슬롯 시작 = 이전 슬롯 끝(또는 `at` 고정 오프셋, 앞이 길면 뒤로 밀림), 장면 길이 = max(마지막 슬롯 끝, `min_dur`). 음성은 슬롯 시작+0.3 s 에 재생. render.js·mux.py 가 같은 계산을 공유.
- 장면 안 연출은 두 가지 시계를 쓴다: (a) 나레이션 진행률 `S.B(f)` — 소개/설명 순서를 음성 길이에 비례해 맞춤(음성이 길어지면 같이 늘어남). (b) 실시간 초 단위 — 신호등 1 s 켜짐/1 s 꺼짐 ×12 + 3 s 소등, 2 s 안정, 3 s 정지처럼 규칙상 실제 시간이 필요한 부분(장면 4, 8, 9). 이런 장면은 `min_dur` 로 최소 길이를 보장한다.
- 장면 4 는 점멸이 실시간이라 나레이션 3조각(s04a 0 s, s04b 14.0 s, s04c 24.2 s)을 고정 오프셋(`at`)으로 배치.
- 장면 9 는 이동·관측을 1.43배 빠르게, 3초 정지는 실시간. s09b(복귀 설명)는 `at` 9.5 s.
- 장면 7 은 박스→장소 왕복 12회를 시뮬레이션(plan.js 경로)해 처음 3회는 보통 속도, 나머지는 타임랩스(배지에 배속 표시). 한 번에 몇 개를 싣는지는 발제에 없으므로 표현하지 않음.

## 7. 재렌더 절차
```
python3 make_timing.py --audio      # audio/s01.wav … 가 있을 때 (SPEED=1.15 기본)
node render.js                      # preview_silent.mp4 (장면 길이는 timing.json 을 그대로 읽음)
python3 mux.py --out final.mp4      # 음성 입히기 (./mux.sh 도 가능)
node render.js --shots              # shots/ 대표 프레임
```
결정성: `Math.random`/`requestAnimationFrame` 미사용. 입자 등은 `hash01(i)` 시드 고정 함수.
