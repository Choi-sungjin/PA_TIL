## 1. RViz 가 실제로 하는 일

처음에 제일 크게 오해한 건 **RViz 를 켜면 뭔가 보여줄 거라고 생각한 것**이다. RViz 는 데이터를 만들지
않는다. 이미 흐르고 있는 토픽을 받아서, TF 를 따라 좌표를 옮긴 다음, 내가 고른 기준 좌표계 위에
그릴 뿐이다.

```text
토픽 (/scan, /odom, /camera/... )  ─┐
                                    ├─→  Fixed Frame 기준으로 변환  ─→  3D 화면
TF   (/tf, /tf_static)             ─┘
```

그래서 RViz 화면에 뭔가 뜨려면 세 가지가 다 맞아야 한다.

| 조건 | 확인 방법 |
|---|---|
| 그릴 토픽을 누군가 퍼블리시하고 있다 | `ros2 topic list`, `ros2 topic hz <토픽>` |
| 그 데이터의 `frame_id` 에서 Fixed Frame 까지 TF 가 이어져 있다 | RViz 의 Global Status, `ros2 run tf2_ros tf2_echo` |
| Display 타입·토픽 이름·QoS 가 맞다 | Display 항목의 Status, `ros2 topic info -v <토픽>` |

Gazebo 나 실제 로봇, `ros2 bag play` 같은 **데이터 공급원이 먼저 떠 있어야 한다.** 08-14 에 Gazebo 없이
RViz 만 켜서 아무것도 안 떴던 게 정확히 첫 번째 조건이 빠진 상황이었다.

## 2. 실행하기

```bash
source /opt/ros/humble/setup.bash
rviz2                          # 기본 실행 (ros2 run rviz2 rviz2 와 같다)
rviz2 -d ~/my_view.rviz        # 저장해 둔 설정 파일로 바로 시작
```

`ros-humble-desktop` 으로 설치했다면 RViz2 는 이미 들어 있다. `ros-base` 만 깔았으면
`sudo apt install ros-humble-rviz2` 로 따로 설치해야 한다. WSL2 에서는 WSLg 덕분에 별도 X 서버 없이
그대로 창이 뜬다 (08-25 에 확인).

## 3. 화면 구성

처음 켜면 패널이 여러 개라 어디부터 봐야 할지 헷갈린다. 역할별로 나누면 이렇다.

| 영역 | 위치 | 하는 일 |
|---|---|---|
| **Displays** | 왼쪽 | 무엇을 그릴지 목록. `Add` 로 추가, 체크박스로 켜고 끄기 |
| **Tool 툴바** | 위 | 마우스 클릭의 의미를 바꾼다 (카메라 이동, 측정, 목표 지점 찍기 등) |
| **3D View** | 가운데 | 실제로 그려지는 화면 |
| **Views** | 오른쪽 | 카메라 방식 (Orbit, TopDownOrtho 등) 과 시점 초기화 |
| **Time** | 아래 | ROS 시간과 Wall 시간. 시뮬레이션·bag 재생 때 확인 |

패널을 실수로 닫았으면 상단 메뉴 `Panels` 에서 다시 켤 수 있다.

## 4. 제일 먼저 볼 것 — Global Options 와 Global Status

Displays 맨 위에 있는 두 항목이 사실상 RViz 의 시작점이다.

### Fixed Frame

**Fixed Frame 은 "모든 데이터를 어느 좌표계로 옮겨서 그릴지"** 를 정하는 값이다. 기본값이 `map` 인데,
SLAM 이나 Nav2 를 안 돌리면 `map` 프레임을 아무도 안 뿌리기 때문에 아무것도 안 그려진다.

- 지금 살아 있는 프레임 목록은 **Fixed Frame 칸의 드롭다운**에 뜬다. 여기서 고르는 게 제일 빠르다.
- 전체 TF 트리를 보고 싶으면 `ros2 run tf2_tools view_frames` → 현재 폴더에 `frames.pdf` 가 생긴다.
- 원칙은 **세상에 대해 움직이지 않는 프레임**을 고르는 것이다. 맵이 있으면 `map`, 없으면 `odom`.
  `base_link` 를 고르면 로봇이 화면 중앙에 고정되고 주변 세상이 움직이는 것처럼 보인다.

08-14 에 Fixed Frame 을 `map` → `base_footprint` 로 바꿔서 화면을 띄웠던 것도 결국 "존재하는 프레임으로
바꿨다" 는 뜻이었다. 다만 `base_footprint` 는 로봇과 같이 움직이는 프레임이라, 스캔을 쌓아서 보거나
경로를 그릴 때는 `odom` 이 더 맞다.

### Global Status

문제가 있으면 여기에 노란색·빨간색으로 뜬다. 자주 보는 메시지만 정리하면:

| 메시지 | 의미 | 할 일 |
|---|---|---|
| `Frame [map] does not exist` | 그 이름의 프레임을 아무도 안 뿌림 | Fixed Frame 을 실제 있는 프레임으로 변경 |
| `No transform from [A] to [B]` | 두 프레임 사이 TF 가 끊김 | `robot_state_publisher`, 정적 TF 가 떠 있는지 확인 |
| Display 의 `No messages received` | 토픽에 데이터가 안 들어옴 | 토픽 이름·퍼블리셔·QoS 확인 (6절) |

**빨간 글씨를 펼쳐서 읽는 것**만으로 원인의 절반은 나온다.

## 5. Display 추가하기 — "By topic" 탭을 쓰자

`Add` 를 누르면 탭이 두 개 있다.

- **By display type**: 타입을 먼저 고르고 토픽 이름은 나중에 손으로 입력한다. 오타가 나기 쉽다.
- **By topic**: **지금 살아 있는 토픽**이 목록으로 뜨고, 그 메시지 타입에 맞는 Display 만 골라준다.

처음에는 By topic 을 쓰는 게 실수가 훨씬 적다. 여기에 원하는 토픽이 안 보이면 RViz 문제가 아니라
**퍼블리셔가 아직 안 떠 있는 것**이다.

자주 쓰는 Display 를 정리하면:

| Display | 메시지 타입 | 주로 보는 토픽 | 메모 |
|---|---|---|---|
| Grid | — | — | 기준 바닥. Fixed Frame 의 XY 평면 |
| TF | `tf2_msgs/TFMessage` | `/tf`, `/tf_static` | 축 색은 X 빨강, Y 초록, Z 파랑 (RGB = XYZ) |
| RobotModel | URDF 문자열 | `/robot_description` | `robot_state_publisher` 가 떠 있어야 함 |
| LaserScan | `sensor_msgs/LaserScan` | `/scan` | 점이 작으면 `Size (m)` 를 키운다 |
| PointCloud2 | `sensor_msgs/PointCloud2` | 깊이 카메라 포인트 | 색은 `Color Transformer` 로 바꾼다 |
| Image | `sensor_msgs/Image` | 카메라 이미지 토픽 | 3D 화면이 아니라 별도 패널에 뜬다 |
| Odometry | `nav_msgs/Odometry` | `/odom` | 화살표로 위치·방향, Keep 개수만큼 남음 |
| Path | `nav_msgs/Path` | `/plan` 등 | 경로를 선으로 |
| Map | `nav_msgs/OccupancyGrid` | `/map` | Durability 주의 (6절) |
| Marker / MarkerArray | `visualization_msgs/...` | 내가 정하는 토픽 | 디버깅용 도형을 직접 그릴 때 |

**타입이 다르면 절대 안 그려진다.** Odometry Display 에 `/scan` 을 넣어도 에러만 날 뿐이다.

## 6. 토픽도 맞고 프레임도 맞는데 안 뜰 때 — QoS

Display 의 `Topic` 항목을 펼치면 `Depth`, `History Policy`, `Reliability Policy`, `Durability Policy`
가 있다. 이게 퍼블리셔와 안 맞으면 연결 자체가 안 된다. 퍼블리셔 쪽 QoS 는 이렇게 확인한다.

```bash
ros2 topic info -v /scan     # Publisher 의 Reliability / Durability 가 나온다
```

Reliability 는 **구독자(RViz) 가 퍼블리셔보다 더 엄격하면 안 된다.**

| 퍼블리셔 | RViz (구독자) | 연결 |
|---|---|---|
| Reliable | Reliable | O |
| Reliable | Best Effort | O |
| Best Effort | Best Effort | O |
| Best Effort | Reliable | **X** |

센서 드라이버는 Best Effort 로 보내는 경우가 많으니, 스캔이나 포인트클라우드가 안 뜨면 RViz 쪽을
`Best Effort` 로 바꿔본다.

Durability 는 `/map`, `/robot_description` 처럼 **한 번만 보내고 끝나는 토픽**에서 문제가 된다.
퍼블리셔가 `Transient Local` 로 보내는데 RViz 가 `Volatile` 이면, RViz 를 나중에 켰을 때 이미 지나간
메시지를 못 받는다. 맵이 안 뜨면 Durability 를 `Transient Local` 로 맞춘다. (QoS 자체는 08-12 정리 참고)

## 7. 화면 조작 — 마우스와 Views

기본 카메라인 **Orbit** 기준 마우스 조작:

| 조작 | 동작 |
|---|---|
| 왼쪽 드래그 | 초점을 중심으로 회전 |
| 가운데 드래그 (또는 `Shift` + 왼쪽 드래그) | 평행 이동 |
| 휠 / 오른쪽 드래그 | 확대·축소 |

시점이 엉뚱한 데로 날아가서 아무것도 안 보이면 오른쪽 Views 패널의 **`Zero`** 버튼으로 초기화한다.
"안 그려진다" 고 생각했는데 사실 카메라가 다른 데를 보고 있는 경우도 있다.

- 2D 맵이나 Nav2 를 볼 때는 Views 의 Type 을 **TopDownOrtho** 로 바꾸면 위에서 내려다보는 평면이 된다.
- Views 의 **Target Frame** 을 `base_link` 로 주면 카메라가 로봇을 따라다닌다. Fixed Frame 은 그대로
  `odom` 이나 `map` 으로 두고 카메라만 따라가게 하는 것이라 둘을 헷갈리면 안 된다.

## 8. 툴바 — 클릭이 곧 토픽이 된다

위쪽 툴바 도구 중 일부는 **화면을 클릭하면 토픽을 퍼블리시**한다. Nav2 에서 "2D Goal Pose" 를 찍으면
로봇이 움직이는 것도 RViz 가 직접 로봇을 움직이는 게 아니라, 찍은 위치를 토픽으로 보내고 Nav2 가 그걸
받아서 움직이는 구조다.

| 도구 | 하는 일 | 퍼블리시 토픽 |
|---|---|---|
| Interact | 인터랙티브 마커 조작 | — |
| Move Camera | 기본 카메라 조작 모드 | — |
| Select | 드래그로 영역 선택, 값은 Selection 패널에서 확인 | — |
| Focus Camera | 클릭한 지점으로 초점 이동 | — |
| Measure | 두 점 사이 거리 측정 | — |
| 2D Pose Estimate | 로봇 초기 위치 지정 (AMCL 등) | `/initialpose` |
| 2D Goal Pose | 목표 위치 지정 (Nav2) | `/goal_pose` |
| Publish Point | 클릭한 지점 좌표 | `/clicked_point` |

2D 도구는 **바닥(XY 평면) 을 클릭해서 위치를 찍고, 누른 채로 드래그해서 방향을 정한다.**
실제로 뭐가 나가는지 보고 싶으면 다른 터미널에서 `ros2 topic echo /goal_pose` 를 띄워두고 찍어보면 된다.

## 9. 로봇 없이 RViz 연습하기 — 정적 TF + Marker

로봇이나 Gazebo 없이도 터미널 두 개면 RViz 에 뭔가를 띄워볼 수 있다. 1절의 세 조건을 손으로 하나씩
채워보는 연습이다.

```bash
# 터미널 1 — map 에서 x 로 1 m, yaw 0.5 rad 돌아간 위치에 base_link 프레임을 만든다
ros2 run tf2_ros static_transform_publisher \
  --x 1 --y 0 --z 0 --yaw 0.5 --pitch 0 --roll 0 \
  --frame-id map --child-frame-id base_link
```

```bash
# 터미널 2 — base_link 위치에 빨간 상자(Marker) 를 1 Hz 로 계속 보낸다
ros2 topic pub -r 1 /visualization_marker visualization_msgs/msg/Marker \
"{header: {frame_id: base_link}, ns: test, id: 0, type: 1, action: 0,
  pose: {orientation: {w: 1.0}},
  scale: {x: 0.3, y: 0.3, z: 0.3},
  color: {r: 1.0, g: 0.0, b: 0.0, a: 1.0}}"
```

```bash
# 터미널 3
rviz2
```

RViz 에서는

1. Fixed Frame 을 `map` 으로 둔다 (이제 터미널 1 이 `map` 을 만들었으니 에러가 사라진다).
2. `Add` → `By display type` → **TF** 추가 → `map` 과 `base_link` 축이 보인다.
3. `Add` → `By topic` → `/visualization_marker` 의 **Marker** 추가 → `base_link` 위치에 빨간 상자.
4. Fixed Frame 을 `base_link` 로 바꿔본다 → 이번엔 상자가 원점에 오고 `map` 축이 반대로 옮겨진다.

4번을 해보면 **Fixed Frame 은 데이터를 바꾸는 게 아니라 "어디를 기준으로 볼지" 만 바꾼다**는 게
눈으로 보인다. Marker 에서 `type: 1` 은 CUBE, `action: 0` 은 ADD 다. `type` 을 2 (SPHERE),
3 (CYLINDER) 로 바꿔보면 모양이 바뀐다.

Marker 는 값을 빼먹으면 조용히 안 보인다.

- `color.a` 를 안 주면 기본값 0 이라 **완전 투명**이 된다.
- `scale` 을 안 주면 크기 0 이라 안 보인다.
- `orientation` 을 안 주면 쿼터니언이 전부 0 이 되어 유효한 회전이 아니다. 최소 `w: 1.0` 은 줘야 한다.

## 10. 설정 저장하고 launch 로 한 번에 띄우기

Display 를 매번 손으로 추가하는 건 번거롭다. 한 번 맞춰놓고 파일로 저장한다.

- `File → Save Config As` (`Ctrl+Shift+S`) 로 `.rviz` 파일 저장, 이후엔 `Ctrl+S`.
- 따로 저장하지 않으면 `~/.rviz2/default.rviz` 가 쓰이고, 다음에 `rviz2` 를 그냥 켜면 그게 열린다.
- 패키지 안 `rviz/` 폴더에 두고 launch 에서 `-d` 로 넘기면 노드와 RViz 가 한 번에 뜬다.

```python
import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    rviz_config = os.path.join(
        get_package_share_directory('my_pkg'), 'rviz', 'view.rviz')

    return LaunchDescription([
        Node(
            package='rviz2',
            executable='rviz2',
            name='rviz2',
            arguments=['-d', rviz_config],
            # Gazebo 나 bag 재생과 같이 쓸 때는 True
            parameters=[{'use_sim_time': False}],
        ),
    ])
```

파이썬 패키지라면 `setup.py` 의 `data_files` 에 `rviz/` 폴더를 넣어줘야 `install/` 의 share 경로로
복사된다. 이걸 빼먹으면 소스 폴더엔 파일이 있는데 launch 에서는 못 찾는다.

```python
(os.path.join('share', package_name, 'rviz'), glob('rviz/*.rviz')),
```

## 11. 화면이 비었을 때 확인 순서

결국 오늘 정리한 걸 순서대로 줄이면 이렇다. 위에서부터 하나씩 지워나간다.

1. **데이터가 있나** — `ros2 topic list`, `ros2 topic hz <토픽>`
2. **타입이 맞나** — `ros2 topic info <토픽>` 의 타입과 Display 타입 비교
3. **Fixed Frame 이 존재하나** — Global Status 의 `does not exist`
4. **TF 가 이어지나** — `ros2 run tf2_ros tf2_echo <Fixed Frame> <데이터 frame_id>`
5. **QoS 가 맞나** — `ros2 topic info -v <토픽>` 과 Display 의 Reliability / Durability
6. **시간이 맞나** — Gazebo·bag 이면 `use_sim_time: True`, bag 은 `ros2 bag play --clock`
7. **그려졌는데 안 보이는 건 아닌가** — 크기, 투명도, 카메라 위치 (`Zero`)

## 13. 헷갈렸던 지점 / 메모

- **Fixed Frame 과 Target Frame 은 다르다.** Fixed Frame 은 모든 데이터를 옮겨 놓는 기준이고,
  Target Frame 은 카메라가 따라다니는 대상이다. 로봇을 따라가며 보고 싶다고 Fixed Frame 을
  `base_link` 로 바꾸면, 스캔을 쌓아 볼 때 지난 점들이 로봇과 같이 끌려다녀서 이상하게 보인다.
  따라가는 건 Target Frame 으로 하고 Fixed Frame 은 `odom` 에 둔다.
- **By topic 탭에 토픽이 안 보이면 RViz 를 의심할 게 아니다.** 그 목록은 지금 살아 있는 토픽이다.
  퍼블리셔 쪽부터 본다.
- **RViz 를 껐다 켜면 설정이 날아가는 줄 알았다.** 실제로는 `~/.rviz2/default.rviz` 에 남는다. 대신
  여러 실습을 오가면 그 파일 하나가 계속 덮어써지니, 실습마다 `.rviz` 를 따로 저장하는 게 낫다.
- **툴바 버튼이 토픽을 쏜다는 걸 몰랐다.** RViz 는 보기만 하는 도구인 줄 알았는데, 2D Goal Pose 처럼
  **사람의 클릭을 메시지로 바꿔주는 입력 장치** 역할도 한다.

## 오늘의 한 줄

> RViz 는 데이터를 만들지 않는다. 살아 있는 토픽을, 이어진 TF 를 따라, 내가 고른 Fixed Frame 위에
> 옮겨 그릴 뿐이다. 화면이 비어 있으면 RViz 가 아니라 이 셋 중 하나를 먼저 의심한다.
