# 2026-10-12 TIL — Mask 는 그대로인데 검출은 사라졌다, V 하한과 최소 면적은 서로 다른 단계를 자른다

> 모듈 3 과제는 기존 비전 노드를 ROS 2 위에서 돌리고, 설정값 하나씩만 바꾼 A/B 실험으로 결과가
> 어떻게 달라지는지 토픽으로 받아서 분석하는 과제다. 오늘은 제출물별 시연 문서를 따라가며
> 원격·로컬 구분 → 기준 실행 → 실험 두 개(A/B 네 묶음) → 목표 없음 확인까지 흐름을 정리했다.
> 입력은 **실시간 카메라가 아니라 저장해 둔 사진을 ROS 토픽으로 보낸 것**이고, 이 구분이 결론의 범위를
> 정한다. 환경은 로컬 PC 의 ROS 2 Lyrical, Python 3.12.3, OpenCV 4.6.0.

---

## 1. 제출물 번호와 진행 순서는 다르다

제출물은 네 개다. 실행 안내(`lv2_module3/README.md`), 개인 분석 보고서(`report.md`), 수신 증거
폴더(`results/`), 저장소 최상위 `README.md`. 시연 번호 `1-3` 은 "제출물 1 의 세 번째 단계"라는 뜻이고,
과제 안내의 수행 단계 1~5 와는 별개의 번호다.

처음에는 번호 순서대로 1 → 2 → 3 → 4 를 하면 되는 줄 알았는데, 그러면 **결과를 본 뒤에 가설을 쓰게
된다.** 그래서 실제 진행 순서는 이렇게 섞인다.

```text
1-1 접속 → 1-2 환경 → 1-3 기준 실행 → 2-1 토픽 → 2-2 가설
→ 3-1 A/B 실행 → 3-2 목표 없음 → 3-3 증거 확인
→ 2-3 분석 → 2-4 선택값 → 2-5 보고서 → 1-4 실행 안내 → 4-1 진입 링크 → 4-2 제출
```

번호는 "어느 파일에 남기나"를 찾기 위한 분류이고, 순서는 "가설이 결과보다 먼저"라는 원칙이 정한다.

## 2. 지금 이 터미널이 어느 컴퓨터인지부터 확인한다

장비가 둘이다. 카메라가 붙은 **원격 장비**와 저장소가 있는 **로컬 PC**. A/B 실험은 로컬에서 저장 사진으로
돌린다.

```bash
hostname; whoami; pwd
```

이 세 줄이 오늘 가장 많이 친 명령이다. 걸렸던 지점이 두 개 있었다.

- **VS Code 원격 창에서 새 터미널을 열면 여전히 원격이다.** `cd` 로는 다른 컴퓨터로 갈 수 없다.
  `File → Close Remote Connection` 으로 원격 연결을 닫고, 왼쪽 아래 `SSH: ...` 표시가 사라진 걸 본 뒤에
  로컬 폴더를 다시 열어야 한다. `whoami` 가 원격 계정 이름이면 아직 전환이 안 된 것이다.
- 문서에 보이는 `user@host:~$` 는 터미널이 찍어주는 **프롬프트**라 입력하지 않는다. 그리고 `;` 는
  혼자 치면 문법 오류지만 `hostname; whoami; pwd` 처럼 명령 사이에 두면 정상적인 구분자다.

로컬로 넘어온 뒤 계산 테스트를 먼저 돌렸다.

```bash
source /opt/ros/lyrical/setup.bash
python3 lv2_module5/tests/test_detector.py     # 7 개 통과
```

여기서 착각하기 쉬운 게, **7 개 통과는 합성 데이터로 계산 함수만 검사한 것**이다. 노드가 실제로 뜨고
토픽이 오가는지는 이 테스트로 알 수 없다. 사전 점검일 뿐이다.

## 3. 새로 만들지 않고, 이미 있는 노드를 찾아서 그대로 쓴다

Mask·Overlay 를 압축 이미지로 발행하는 기능을 새로 짤 필요가 없었다. 원격 장비의 기존 프로젝트를
뒤져서(Python 파일 483 개) 이미 그 기능이 있는 라이브 뷰 노드를 찾았고, **수정 없이 복사해서** 썼다.
복사할 때 원본 경로와 SHA-256 을 같이 기록해 뒀다. 나중에 "이 결과가 정말 그 코드에서 나왔나"를
보여줄 수 있는 근거가 해시다.

실행을 돕는 스크립트는 저장 사진을 토픽으로 보내고, 노드·뷰어·수신 도구를 띄우고, 증거를 저장하고,
자기가 띄운 프로세스를 정리하는 일만 한다. **검출 알고리즘은 건드리지 않는다.** 기준 실행이 성공하면
이렇게 나온다.

```text
PASS: 4 same-frame ROS messages, input pixels match, RViz window captured
```

공개 저장소에는 권한이 없는 원본 코드를 그대로 올리지 않고, 출처와 해시, 필요한 최소한의 설명만 남긴다.

## 4. 토픽 목록에 이름이 보인다고 성공이 아니다

이번에 직접 받은 토픽은 네 개다.

| 자료 | 토픽 | 메시지 타입 | 확인 도구 |
|---|---|---|---|
| 원본 | `/camera/camera/color/image_raw` | `sensor_msgs/msg/Image` | RViz |
| Mask | `/target/debug/mask/compressed` | `sensor_msgs/msg/CompressedImage` | `rqt_image_view` |
| 검출 표시 | `/target/debug/overlay/compressed` | `sensor_msgs/msg/CompressedImage` | RViz |
| 검출 수치 | `/target` | `geometry_msgs/msg/PointStamped` | 수신 도구 |

Mask·Overlay·수치는 검출 노드 `/target_detector` 가 발행하고, 원본은 `ros2 topic pub` 으로 띄운 노드가
보낸다(이름은 실행마다 바뀐다). 성공 판정 기준은 **같은 프레임의 메시지 네 개를 실제로 받았는가**다.
`ros2 topic list` 에 이름이 떠 있는 건 발행자가 존재한다는 것까지만 말해준다.

RViz 에서 압축 토픽을 볼 때 설정에 `/compressed` 까지 붙인 전체 이름을 적어야 했다. 앞부분 이름만
적으면 엉뚱한 토픽을 구독할 수 있다. 그리고 RViz 의 Global Status 경고는 저장 사진 실행이라 TF 가 없어서
뜬 것이었고, 영상 수신 여부와는 따로 확인했다(07 일에 정리한 "TF 가 이어져야 그려진다"의 연장이다).

## 5. 실험 설계 — 값 하나만 바꾸고, 매번 노드를 새로 띄운다

검출 노드는 **시작할 때 설정을 읽는다.** 그래서 A 와 B 는 각각 노드를 새로 시작해야 하고, 실험 2 를
시작할 때도 실험 1 의 B 가 아니라 A 설정으로 돌아가서 시작한다.

| | 바꾼 값 | A | B | 실행 전 예상 |
|---|---|---|---|---|
| 실험 1 | HSV 의 V(밝기) 하한 | 40 | 180 | 어두운 파란 영역이 Mask 에서 빠진다 |
| 실험 2 | 최소 윤곽선 면적 | 100 px² | 5000 px² | Mask 는 그대로, 후보만 탈락한다 |

고정한 것: 같은 640×480 사진, 나머지 HSV(H 102~110, S 120~255)·형태학 설정, 깊이 사용 끔, 물체
추적 끔. 두 실행의 설정 파일을 `diff` 해 보면 바꾼 한 줄과 로그 저장 경로만 다르게 나온다. 그래야
결과 차이를 그 한 줄 탓으로 돌릴 수 있다.

## 6. 결과 — 같은 프레임 네 메시지에서 읽은 값

| 묶음 | Mask 픽셀(>127) | Mask 고유값 개수 | `/target` z | 검출 |
|---|---:|---:|---:|---|
| exp1-A | 4073 | 70 | 0.012846680 | 있음 |
| exp1-B | 0 | 1 | 0 | 없음 |
| exp2-A | 4073 | 70 | 0.012846680 | 있음 |
| exp2-B | 4073 | 70 | 0 | 없음 |
| absent (목표 없음 사진) | 0 | 1 | 0 | 없음 |

다섯 묶음 모두 `receipt.json` 의 `success` 가 `true` 였다.

- **실험 1** 은 예상대로 Mask 자체가 4073 → 0 으로 비었다. 밝기 하한을 180 으로 올리니 어두운 파란
  목표가 색 조건을 통과하지 못했다. 자르는 위치가 **Mask 를 만드는 단계**다.
- **실험 2** 는 Mask 가 픽셀 하나까지 같은데 z 만 0 이 됐다. 목표의 윤곽선 면적이 3946.5 px² 라서
  최소 면적 5000 에 못 미쳐 후보에서 빠졌다. 자르는 위치가 **Mask 다음, 윤곽선을 고르는 단계**다.

처리 흐름으로 놓으면 두 값이 어디를 자르는지 바로 보인다.

```text
원본 Image → HSV 변환 → inRange (V 하한: 실험 1) → open·close 잡음 제거 → Mask 발행
           → findContours → 면적 ≥ 최소 면적 (실험 2) → 후보 선택 → /target·Overlay 발행
```

둘 다 결과는 "검출 없음"이지만, Mask 화면을 같이 보지 않았으면 **어느 단계에서 떨어졌는지 구분할 수
없었다.** 디버그 Mask 토픽을 따로 발행하는 이유가 이거였다.

## 7. z 는 거리가 아니었다

`/target` 은 `PointStamped` 라서 처음엔 z 를 당연히 깊이(거리)로 읽었다. 이 코드에서는 아니다.

- x, y: 영상 중심 기준으로 정규화한 오차
- z: 윤곽선 면적 ÷ 영상 전체 면적

검산해 보면 맞아떨어진다.

```math
z \times (640 \times 480) = 0.0128466796875 \times 307200 = 3946.5\ \text{px}^2
```

실험 2 에서 본 윤곽선 면적 3946.5 px² 가 그대로 나온다. 그래서 이 코드의 "미검출"은 x = y = z = 0
이고, 반대로 x = y = 0 이어도 z > 0 이면 **목표가 화면 정중앙에 있는 것**일 수 있다. 메시지 타입 이름만
보고 필드 의미를 추측하면 안 되고, 발행 코드를 봐야 한다.

## 8. Mask 픽셀 수와 윤곽선 면적은 다른 숫자다

같은 exp1-A 에서 Mask 픽셀은 4073 인데 윤곽선 면적은 3946.5 다. 처음엔 둘이 같아야 한다고 생각했는데
두 가지 이유로 다르다.

1. **Mask 가 JPEG 로 압축돼서 온다.** 원래 0/255 두 값뿐인 이진 영상인데, 받아서 풀어 보면 고유값이
   70 개다. 경계에 회색이 번진다. 그래서 픽셀 수는 "127 보다 큰 픽셀"이라는 기준을 정해서 셌다.
   기준을 바꾸면 숫자도 바뀐다.
2. **`contourArea` 는 픽셀 개수를 세지 않는다.** 경계 픽셀의 중심점들을 이은 다각형의 넓이라서,
   가장자리 픽셀이 절반쯤 빠진 값이 나온다.

목표가 없는 사진(absent)과 실험 1-B 는 Mask 고유값이 1 개, 전부 0 이었다. 압축으로 생기는 회색도
**흰 영역이 있어야** 생긴다.

## 9. 저장 사진 재생과 실시간 카메라는 다른 실험이다

실시간 카메라 원본을 RViz 에 띄우는 데까지는 됐다. 그런데 네 토픽을 같은 프레임으로 묶어 받는 건 끝내
실패했다. 수신 기록에는 시간 안에 같은 프레임의 묶음을 하나도 완성하지 못했다고 남았다.

원인으로 보이는 건 기존 라이브 뷰 코드의 조건이다. 입력 영상의 시각이 **0.5 초보다 오래되면 버린다.**
이번 원격 입력의 지연은 약 0.65 ~ 0.82 초였다. 0.5 초 기준을 넘으니 프레임이 계속 버려졌을 가능성이
크다. 컬러만 남기고 재시작해도 결과는 같았다.

그래서 오늘의 A/B 결론은 **"저장 사진을 ROS 토픽으로 보냈을 때"로 범위를 한정**한다. 보고서에 이걸
"실시간 카메라 실험"으로 적으면 안 된다. 8 일에 "bag 재생이 재현하는 건 기록된 메시지까지"라고 적었던
것과 같은 구조다. 입력이 어디서 왔는지가 결론이 덮는 범위를 정한다.

## 11. 막혔던 지점 / 메모

- **"테스트 통과", "토픽이 목록에 있음", "같은 프레임 네 메시지 수신"은 서로 다른 층이다.** 앞의 두
  개는 세 번째를 보장하지 않는다. 성공 기준을 가장 바깥 층에 둬야 한다.
- **결과는 같아도 떨어진 단계는 다를 수 있다.** 실험 1-B 와 2-B 는 `/target` 만 보면 똑같이 0 이다.
  Mask 를 같이 봐야 색 조건에서 떨어졌는지, 면적 조건에서 떨어졌는지 갈린다.
- **필드 이름은 의미를 보장하지 않는다.** `PointStamped` 의 z 가 거리가 아니라 면적비였다.
- **압축은 숫자를 바꾼다.** 이진 Mask 를 JPEG 로 보내면 회색이 생기고, 픽셀 수는 문턱값에 따라 달라진다.
  보고서에는 "127 초과 픽셀 수"처럼 세는 기준까지 적어야 한다.
- 선택값은 이 사진에서 목표를 남긴 V 하한 40, 최소 면적 100 이다. 목표 없는 사진에서는 x = y = z = 0
  으로 오검출이 없었다. 다만 사진 한 장, 조명 한 가지에서 나온 값이라 **다른 조명·배경에서도 맞는다고
  일반화하지 않는다.**
- 시연 문서의 수치와 캡처는 예시다. 보고서는 내가 돌린 `results/run-*` 폴더의 결과로 다시 써야 한다.
