## 1. 이름부터 종류가 다르다

처음에 PPO, SB3, RSL-RL, Gymnasium 이 다 같은 급의 이름인 줄 알았다. 층으로 나누면 이렇다.

| 층 | 이름 | 하는 일 |
|---|---|---|
| 로봇 자산 | URDF · USD · MJCF | 링크·관절·질량 기술 (신경망 아님) |
| 물리 | MuJoCo · Isaac Sim(PhysX) | 관절·접촉 계산 |
| 환경 규약 | Gymnasium · Isaac Lab 태스크 | reset · step, 관측·행동·보상 정의 |
| 알고리즘 | PPO | 정책을 조금씩 고치는 **방법** |
| 구현 | SB3 · RSL-RL | 그 방법을 실행하는 **소프트웨어** |

오늘 경로는 두 줄이다.

```text
필수 : 내 URDF → MJCF → MuJoCo → Gymnasium 환경 → SB3 PPO
확장 : 내 USD  → Isaac Sim PhysX → Isaac Lab 태스크 → RSL-RL PPO
```

같은 PPO 라도 구현·정규화·하이퍼파라미터가 다르면 결과가 달라지고, **두 경로의 체크포인트는 그대로 바꿔
끼우지 않는다.** "PPO 로 학습했다"는 말만으로는 재현이 안 된다는 뜻이다.

## 2. 정책은 로봇을 "보지" 않는다

| 단어 | 뜻 |
|---|---|
| State | 시뮬레이터 안의 전체 값 (위치·속도·접촉·물성) |
| Observation | 그중 정책에 **실제로 넘겨주는** 배열 |
| Action | 정책이 내보내는 명령 (토크·속도·위치 목표) |
| Transition | (관측, 행동, 보상, 다음 관측) 한 묶음 |
| Rollout | transition 을 모은 것 |

한 스텝은 `o_t → 정책 → a_t → 구동기 → 물리 → o_(t+1), r_t, 종료` 순서고, 평가 때도 순서는 같고
가중치만 안 바꾼다.

중요한 문장: **목표가 바뀌는 과제라면 목표(또는 목표 오차)를 관측에 넣어야 한다.** 바퀴 목표 속도가 +2 rad/s 인
에피소드와 −2 rad/s 인 에피소드에서 로봇 상태가 똑같다면, 목표가 관측에 없을 때 정책은 같은 입력을 받으니
같은 행동밖에 못 낸다. 둘 중 하나는 반드시 틀린다.

Transition 정의를 보니 지난번 Cartpole 이 생각났다. 환경 1개 × 300 반복으로 돌렸을 때 모인 경험은 4,800
transition 뿐이었고 학습이 안 됐다. 환경 16개로 늘리자 같은 반복 수에서 16배를 모았고 학습이 됐다.
반복 횟수가 아니라 **모은 transition 수**로 세야 했다.

## 3. MLP 의 입력·출력 크기는 관절 수가 아니라 설계가 정한다

슬라이드: "관절 8개라고 관측도 8개인 것은 아닙니다." 내 v96 으로 세어 봤다.

| 항목 | 개수 |
|---|---:|
| 링크 | 16 |
| 관절 전체 | 15 |
| 고정 관절 (카메라·라이다 프레임 등) | 4 |
| 움직이는 관절 | **11** |
| └ 바퀴 2 · 팔 4(어깨·팔꿈치·손목·툴 롤) · 리프트 1 · 집게 2 · 캐러셀 1 · 아이들러 1 | |
| 집게 아래쪽은 위쪽을 따라감(mimic) → 독립 | 10 |

그런데 첫 과제를 "바퀴 두 개의 속도 추종"으로 잡으면 행동은 **2개**다. 관측은 예를 들어
`[왼 바퀴 속도, 오른 바퀴 속도, 왼 목표, 오른 목표, 직전 행동 2개]` 로 6개. 11이라는 숫자는 어디에도 안 나온다.

은닉층을 64-64 로 두고 Actor·Critic 을 따로 만든다고 가정하면 가중치 개수는

```text
Actor  : 6·64+64 + 64·64+64 + 64·2+2 + (행동 표준편차 2) = 4,740
Critic : 6·64+64 + 64·64+64 + 64·1+1                    = 4,673
합계                                                    ≈ 9,400
```

이 숫자들이 **Parameter**(학습으로 바뀌는 것)이고, 64-64 라는 크기나 learning_rate 는 **Hyperparameter**(내가
정하는 것)다. Actor 는 행동 분포를, Critic 은 예상 수익 V 를 내고, **Critic 은 모터에 명령을 내리지 않는다.**
Critic 의 출력은 Advantage 계산에만 쓰인다.

## 4. 보상 · 수익 · 가치 · Advantage

$$
G_t = \sum_{k=0}^{T-t-1} \gamma^k r_{t+k}, \qquad A_t \approx G_t - V(o_t)
$$

슬라이드 예시를 직접 계산: 보상 1, 2, 3, γ = 0.9 →
$G = 1 + 0.9·2 + 0.81·3 = 5.23$, V = 4 면 A = 1.23. 예상보다 1.23 만큼 좋았으니 그 행동의 확률을 올린다.
($A \approx G - V$ 는 직관용이고 실제 구현은 GAE 로 여러 길이의 추정을 섞는다. `gae_lambda` 가 그 비율.)

### γ 는 "스텝" 단위라서 초로 바꾸려면 주기가 필요하다

노트의 한 줄 "제어 주기를 바꾸면 같은 gamma 의 시간 의미도 바뀐다"를 숫자로 풀었다. γ = 0.99 일 때
가중치 합은 $1/(1-\gamma) = 100$ 스텝, 가중치가 절반이 되는 지점은 $\ln 0.5 / \ln 0.99 \approx 69$ 스텝이다.

| 제어 주기 | 100 스텝 | 반감 69 스텝 |
|---:|---:|---:|
| 25 Hz | 4.0 s | 2.8 s |
| 50 Hz | 2.0 s | 1.4 s |
| 100 Hz | 1.0 s | 0.69 s |
| 500 Hz | 0.2 s | 0.14 s |

같은 0.99 인데 25 Hz 면 4초 앞을, 500 Hz 면 0.2초 앞을 본다. 슬라이드의 에피소드 예가 "목표 이동 10초"인데,
500 Hz 로 돌리면 정책은 10초짜리 과제에서 0.2초 앞만 신경 쓰는 셈이다. 주기를 dt₁ → dt₂ 로 바꾸면서 시간
의미를 유지하려면 $\gamma_2 = \gamma_1^{dt_2/dt_1}$. 예: 50 Hz 의 0.99 → 100 Hz 에서는 $0.99^{0.5} = 0.995$.

## 5. PPO 의 clip — 한쪽만 막는다

$$
\rho_t = \frac{\pi_\theta(a_t|o_t)}{\pi_{old}(a_t|o_t)},\qquad
L = \mathbb{E}\left[\min\left(\rho_t A_t,\ \mathrm{clip}(\rho_t, 1-\varepsilon, 1+\varepsilon) A_t\right)\right]
$$

ε = 0.2 면 구간은 [0.8, 1.2]. 25장 그래프를 표로 옮겨서 **기울기가 어디서 0 이 되는지** 봤다.

| ρ | A = +1 목적식 | 기울기 | A = −1 목적식 | 기울기 |
|---:|---:|---:|---:|---:|
| 0.6 | 0.6 | **1** | −0.8 | 0 |
| 1.0 | 1.0 | 1 | −1.0 | −1 |
| 1.4 | 1.2 | 0 | −1.4 | **−1** |

- A > 0 (좋았던 행동): ρ 가 1.2 를 넘으면 평평해져서 **더 키울 이유가 없어진다.** 그런데 ρ 가 0.8 아래로
  잘못 내려가 있으면 기울기가 살아 있어서 되돌린다.
- A < 0 도 거울상이다. 0.8 아래로는 더 줄일 이유가 없고, 1.2 위로 잘못 올라간 건 계속 끌어내린다.

그래서 clip 은 "ρ 를 [0.8, 1.2] 에 가둔다"가 아니다. **개선 방향으로 너무 멀리 가려는 유인만 없앤다.** 여러
epoch·minibatch 를 돌면 실제 ρ 는 구간 밖으로 나갈 수 있다(슬라이드도 그렇게 말한다).

### ε 은 행동 단위가 아니다

연속 행동이면 π 는 가우시안 밀도다. 표준편차 σ 는 그대로 두고, 평균에서 1σ 떨어진 곳에서 뽑힌 행동이 있다고
하자. 평균을 그쪽으로 dσ 만큼 옮기면

$$
\rho = \exp\left(\frac{1-(1-d)^2}{2}\right)
$$

- d = 0.1 → ρ ≈ 1.10
- ρ = 1.2 가 되는 건 d ≈ **0.20**

즉 ε = 0.2 의 경계는 "평균을 σ 의 20 % 쯤 옮기는 것"과 비슷한 크기이고, 모터 출력이나 rad/s 와는 상관없다.
모터 한계는 따로 **구동기 설정과 행동 스케일**에서 정한다(23장). 내 v96 바퀴는 URDF 에 토크 3 N·m,
속도 7.88 rad/s 로 적혀 있는데, 이건 정책이 아니라 모델 쪽 숫자다.

학습 로그의 entropy(행동 분포가 퍼진 정도), value loss(가치 예측 오차), approx_kl(정책이 바뀐 정도)도 이
목적식 주변의 지표일 뿐, **이것만으로 과제 성공을 판정하지 않는다.**

## 6. 첫 목표 — 바퀴가 공중에서 돌아도 점수는 만점

26장 표에서 내 v96 은 바퀴 + 팔 + 집게 + 캐러셀이라 **"복합 로봇"** 이고, 시작 과제는 "하나의 구동부 동작"이다.
가장 쉬운 건 바퀴 두 개의 속도 추종이다.

URDF 에서 숫자를 꺼내 봤다.

| 값 | 출처 | 계산 |
|---|---|---|
| 바퀴 반지름 r | 충돌 실린더 | 0.0335 m |
| 바퀴 간격 b | 두 바퀴 관절 원점 차이 | 0.273 − (−0.015) = 0.288 m |
| 최대 바퀴 속도 | limit | 7.88 rad/s |
| 미끄러짐 없을 때 최고 직진 속도 | $r\omega$ | 0.0335 × 7.88 ≈ **0.26 m/s** |
| 제자리 회전 최고 각속도 | $2r\omega/b$ | ≈ **1.83 rad/s** |

여기서 슬라이드가 짚은 함정: **$v = r\omega$ 는 미끄러지지 않을 때만 성립한다.** 보상이 바퀴 관절 속도 오차만
보면, 로봇을 들어 올려 바퀴가 허공에서 7.88 rad/s 로 돌아도 점수는 만점이고 몸체 속도는 0 m/s 다. 관절 속도
추종과 몸체 주행은 다른 과제다. 주행으로 넘어가려면 **몸체 속도·접촉·전복 조건**을 관측과 보상에 넣어야 한다.

그리고 다른 예제(Ant 는 관절 8개)의 관절 수나 보상 계수를 내 로봇에 복사하지 않는다. 재사용하는 건 학습
흐름과 함수 계약(reset · step 이 무엇을 돌려주는지)뿐이다.

## 8. 막혔던 지점 / 메모

- **PPO 는 방법, SB3·RSL-RL 은 구현.** 체크포인트는 경로 사이에 그대로 못 옮긴다.
- **관측에 목표가 없으면** 같은 상태에서 다른 목표를 구별할 수 없다.
- **입출력 크기는 과제 설계가 정한다.** 관절 11개 로봇의 첫 정책 출력은 2개다.
- **γ 는 스텝 단위.** 주기와 같이 적어야 몇 초 앞을 보는지 알 수 있다.
- **clip 은 한쪽만 막는다.** 잘못 간 방향은 계속 되돌린다. ε 은 모터 단위가 아니다.
- **관절 점수 ≠ 주행 성능.** 허공에서 도는 바퀴도 만점이다.
