## 1. 링크는 부품 개수가 아니라 "같이 움직이는 덩어리" 개수다

7장의 기준은 세 줄이다.

- 서로 고정된 부품은 같은 링크로 묶는다.
- 움직이는 경계에만 관절을 둔다.
- 모든 CAD 바디는 **정확히 한 링크**에 속해야 한다.

M38 은 CAD 바디 3,568개를 링크 9개로 묶었다. 본체 1개 + 조향부 4개 + 바퀴 4개이고, 관절은 조향 4개와
바퀴 회전 4개라서 8개다.

```text
base_link
  ├─ lh1_steer → lh1_wheel
  ├─ rh1_steer → rh1_wheel
  ├─ lh2_steer → lh2_wheel
  └─ rh2_steer → rh2_wheel
```

트리이므로 링크가 $n$ 개면 관절은 $n-1$ 개다. $9 - 1 = 8$ 이 맞는다. 팔은 CAD 에 있지만 현재 자세로
**고정**해서 본체에 포함했다. 팔의 자유도를 모델에 넣지 않았으니 이 모델로 팔에 대해서는 아무것도 주장할 수
없다는 뜻이다.

"정확히 한 링크"가 왜 중요한지 생각해 봤다. 바디 하나가 두 링크에 들어가면 질량이 두 번 세지고, 아무 링크에도
안 들어가면 그 부품은 시뮬레이션에서 그냥 사라진다. 둘 다 눈으로는 잘 안 보이는 오류다.

## 2. 단위와 좌표를 먼저 맞춘다 — 행렬 C 를 직접 곱해 봤다

8장의 변환은 이렇다.

```text
v_local = C @ v_CAD_mm / 1000 - origin_m

C = [[ 0, 1, 0],
     [-1, 0, 0],
     [ 0, 0, 1]]
```

예시 `[100, 200, 30] mm` 를 직접 곱하면

```text
C @ [100, 200, 30] = [200, -100, 30]   →  /1000  →  [0.2, -0.1, 0.03] m
```

슬라이드 값과 같다. 확인한 것 두 가지.

- $\det C = 1$ 이다. 즉 C 는 거울 반사가 아니라 **z 축 둘레 −90° 회전**이다. 행렬식이 −1 이었다면 오른손
  좌표계가 왼손으로 뒤집혀서 회전 방향이 전부 반대가 됐을 것이다(9월 초에 회전행렬의 행렬식을 확인했던 이유가
  이거였다).
- CAD 의 y 가 ROS 의 x(전방)가 되고, CAD 의 x 가 ROS 의 −y 가 된다. ROS 기준은 **X 전방, Y 좌측, Z 위쪽**이다.

주의할 점은 이 C 가 **M38 CAD 의 축 배치에만** 맞는 행렬이라는 것이다. 일반적인 관절 변환은
$T_{parent \to child} = T_{world,parent}^{-1}\, T_{world,child}$ 로 구한다. 위의 "원점을 빼기"는 영점 자세에서
링크 좌표축이 월드와 정렬돼 있을 때만 쓸 수 있는 단순한 경우다.

## 3. 관절 축 부호는 0 rad 에서는 절대 안 보인다

9장은 관절을 두 값으로 정의한다.

- `origin` : 부모 링크에서 본 관절의 위치·방향
- `axis` : 관절 좌표계에서 본 회전 방향

그리고 검사를 **0, +0.3, −0.3 rad** 세 자세에서 하라고 한다. 처음엔 왜 0 만으로 부족한지 몰랐는데,
축 부호가 틀린 경우를 생각하면 바로 보인다.

```text
축이 맞을 때   :  명령 +0.3 → 실제 +0.3 rad
축이 반대일 때 :  명령 +0.3 → 실제 −0.3 rad
명령 0         :  둘 다 0  → 구별 불가
```

원점 위치만 맞고 축 부호가 틀리면 0 rad 에서는 완벽해 보이고, 움직이는 순간 반대로 돈다. 0.3 rad 은 약 17.2° 라서
바퀴 중심 위치 차이가 눈에 띌 만큼 크다. 오른쪽 모듈은 왼쪽을 **거울 배치**했기 때문에 부호가 뒤집히기 쉬운
곳이 바로 거기다.

## 4. 질량과 관성 — 4 kg 은 가정값이다

11장의 질량표.

| 링크 | 개수 | 각 질량 | 합계 | 비율 |
|---|---:|---:|---:|---:|
| base_link | 1 | 1.8 kg | 1.8 kg | 45 % |
| steer | 4 | 0.4 kg | 1.6 kg | 40 % |
| wheel | 4 | 0.15 kg | 0.6 kg | 15 % |
| 합계 | 9 | | **4.0 kg** | |

비율 열은 내가 계산했다. 중요한 건 이 값들이 **실측이 아니라 가정값**이라는 점이다. 주행 시험 화면마다 "4 kg
assumed" 가 붙어 있는 이유다. 강도·체결·배선은 이 모델의 검증 범위 밖이다(5장).

관성은 질량중심 기준 $\mathrm{kg\cdot m^2}$ 이고, 박스 근사면

$$
I_{xx} = \frac{m(y^2 + z^2)}{12},\quad I_{yy} = \frac{m(x^2 + z^2)}{12},\quad I_{zz} = \frac{m(x^2 + y^2)}{12}
$$

정적 검사는 관성이 **유효한지**를 본다. 조건은 고윳값이 모두 양수일 것, 그리고 삼각 부등식
$I_{xx} + I_{yy} \ge I_{zz}$ (세 조합 모두)이다. 박스 공식을 넣어 보면

$$
I_{xx} + I_{yy} = \frac{m(x^2 + y^2 + 2z^2)}{12} \ge \frac{m(x^2 + y^2)}{12} = I_{zz}
$$

이라서 박스로 만든 관성은 항상 통과한다. 반대로 CAD 에서 뽑은 관성을 좌표 회전($I_{new} = R I R^T$) 없이 다른
축에 그대로 붙이거나, 손으로 숫자를 고치다가 이 부등식이 깨지면 물리적으로 존재할 수 없는 물체가 된다.

## 5. URDF 와 USD 는 같은 관절을 다른 단위로 적는다

URDF 링크에는 `<inertial>`, `<visual>`, `<collision>` 이 들어가고(13장), 관절에는 parent/child, origin, axis,
limit 이 들어간다(14장). USD 쪽은 물리 API 를 prim 에 붙이는 방식이다(16장).

| 대상 | USD 에서 필요한 설정 |
|---|---|
| Stage | `metersPerUnit=1`, `upAxis=Z`, `kilogramsPerUnit=1` |
| /Robot | defaultPrim, `ArticulationRootAPI` |
| 각 링크 | `RigidBodyAPI`, `MassAPI` |
| 충돌 형상 | `CollisionAPI` |
| 관절 | `RevoluteJoint` + body0/body1 |
| 장면 | `PhysicsScene`, 바닥은 시험에 맞게 |

여기서 놓치기 쉬운 것: **USD 의 부모·자식 prim 계층만으로는 물리 관절이 생기지 않는다.** 관절은 body0/body1 로
명시해야 한다. 그리고 URDF 를 만들었다고 물리 계산을 한 것도 아니다. URDF 는 기술일 뿐이고 계산은 MuJoCo 나
PhysX 가 한다(6장).

17장의 대응표가 오늘 제일 많이 들여다본 표다.

| 항목 | URDF | USD |
|---|---|---|
| 회전 한계 | radian | **degree** |
| 연결 | parent / child | body0 / body1 |
| 관절 위치 | origin | localPos0 / localPos1 |
| 축 방향 | axis + origin rpy | axis + localRot0 / localRot1 |
| 예: 90° | 1.5707963 | 90.0 |

두 가지를 더 메모했다.

- USD 의 회전 관절 축은 X·Y·Z 중 하나만 고를 수 있다. URDF 처럼 임의의 벡터를 축으로 줄 수 없으니, 기울어진 축은
  `localRot` 로 관절 프레임 자체를 돌려서 표현한다.
- USD 쿼터니언은 **실수부 w 가 먼저**(wxyz)다. SciPy 의 `as_quat()` 는 xyzw 순서라서 그대로 복사하면 회전이
  엉뚱해진다.

### 단위를 틀리면 얼마나 틀리나

18장의 실습이 USD 상한을 `90` 대신 `1.5707963` 으로 넣어서 오류를 일부러 만드는 것이다. 숫자로 풀어 봤다.

| 실수 | 의도 | 실제로 해석되는 값 | 배율 |
|---|---|---|---|
| USD 에 라디안 값을 넣음 | ±90° | **±1.57°** | 1/57.3 |
| URDF 에 도 값을 넣음 | ±90° | ±90 rad ≈ **±5157°** (약 14.3바퀴) | 57.3 |

앞의 경우는 관절이 거의 안 움직이고, 뒤의 경우는 사실상 한계가 없다. 두 경우 모두 **파일 문법은 멀쩡하다.**
XML·USD 파서는 아무 경고 없이 읽는다. 그래서 두 형식을 서로 비교하는 검사기가 필요하고, 그게 `angle unit
mismatch` 를 잡는 것이다.

## 6. 값을 바꿀 때는 입력 하나만 고친다

15장 실습은 `model.json` 에서 arm 질량을 0.2 → 0.3 kg, 관절 origin 의 z 를 0.1 → 0.12 m 로 바꾸고 다시 생성한다.
확인할 것은 **두 형식이 함께 바뀌는가**다. URDF 의 `<origin>` 과 USD 의 `localPos0` 이 같이 0.12 가 돼야 한다.

원본 M38 생성기는 JSON 까지 다시 써 버리는 구조라서, JSON 만 손으로 고치고 생성기를 돌리면 고친 값이 사라진다.
입문 실습은 그래서 `model.json` 을 명시적인 입력으로 분리했다. URDF 나 USD 를 직접 고치지 않고 **입력 하나를 고쳐서
둘 다 다시 만드는 것**이 두 형식이 어긋나지 않게 하는 유일한 방법이라고 이해했다.

## 7. 정적 검사의 2×10⁻⁷ m 는 어디서 나온 숫자인가

19장의 정적 검사 기준.

| 검사 | M38 기준 |
|---|---|
| 구조 | 링크 9 / 구동 관절 8 / base_link |
| 메시·수치 | 경로 존재 / NaN·Inf 없음 |
| 물성 | 총질량 4 kg / 유효 관성 |
| 형식 간 비교 | 질량·원점·축·연결 일치 |
| 메시 경계 | 좌표 차이 < 2×10⁻⁷ m |
| 독립 FK | 0, +0.3, −0.3 rad |

메시 경계 허용치가 왜 0.2 µm 일까 궁금해서 float32 의 간격을 계산해 봤다. 메시 좌표는 보통 32비트 실수로 저장한다.

| 좌표 크기 | float32 한 칸(ulp) |
|---:|---:|
| 0.25 m | 3.0×10⁻⁸ m |
| 0.5 m | 6.0×10⁻⁸ m |
| 1.0 m | 1.2×10⁻⁷ m |

로봇 크기가 1 m 안쪽이면 2×10⁻⁷ m 는 float32 몇 칸 차이다. 즉 이 기준은 "**반올림 오차를 빼면 같은 점**"이라는
뜻으로 읽었다. 슬라이드가 이유를 적은 건 아니고 내 해석이다.

M38 원본 검사 결과는 `PASS_FILE_AND_CROSS_FORMAT_VALIDATION` 이고 `physics_runtime=NOT_EXECUTED` 가 같이 적혀
있다. 이 이름이 정확하다. **파일과 형식 간 대응은 통과, 물리는 아직 안 돌렸다.** 정적 검사가 PASS 라고 주행이
된다는 말은 아니다.

## 8. 주행 시험 — 숫자를 세어 보면

MuJoCo 시험(21장)은 마찰계수 0.3 / 0.6 / 0.9 × 동작 4가지(전진·횡이동·대각선·제자리 회전) = **12조건**, 모두
PASS 였다. 각 시험은 10 s 이고 구간은

```text
2 s 안정화 → 1 s 가속 → 4 s 유지 → 1 s 감속 → 2 s 정지      (합 10 s)
```

$dt = 0.002$ s 이므로 시험 하나가 5,000 스텝, 12조건이면 60,000 스텝이다.

궤적 그래프(25장)에서 전진은 약 0.75 m, 대각선은 약 (0.5, 0.5) m 까지 간다. 그래프에서 읽은 값으로 최고 속도를
역산해 보면, 사다리꼴 속도에서 이동거리는 $v_{max} \times (0.5 + 4 + 0.5) = 5\,v_{max}$ 이므로

| 동작 | 이동거리 (그래프 판독) | $v_{max}$ |
|---|---:|---:|
| 전진 | ≈ 0.75 m | ≈ 0.15 m/s |
| 대각선 | ≈ 0.71 m | ≈ 0.14 m/s (x·y 각 0.1 m/s) |

저속 시험이라는 게 숫자로 보인다(4장 "평지·저속" 가정).

Isaac Sim 시험(22장)은 `m38.usd` 로 articulation 을 구성하고, **DOF 이름으로 관절 순서를 매핑**한다. 인덱스 순서를
가정하면 조향 명령이 바퀴로 가는 식의 사고가 난다(28장 "관절이 다른 부위를 움직임"). 그리고 원래 drive 의
gain 을 0 으로 꺼서 외부 제어기만 effort 로 제어한다. 네이티브 drive 와 외부 제어기를 동시에 쓰면 두 제어기가
같은 관절을 서로 당기게 된다.

## 9. 도착했는데 FAIL

23장의 Isaac 합격 기준과 24장의 결과를 같이 놓았다.

| 시험 | 위치 오차 | 최대 조향 속도 | 결과 |
|---|---:|---:|---|
| 전진 | 2.662 mm | 0.9314 rad/s | PASS |
| 횡이동 | 3.182 mm | 0.9016 rad/s | PASS |
| 대각선 | 4.349 mm | **1.0142 rad/s** | **FAIL** |
| 회전 | 0.422 mm | 0.9846 rad/s | PASS |

기준은 위치 오차 < 0.05 m, 조향 각속도 ≤ 1.001 rad/s 다. 각 기준에 대해 **허용치의 몇 %를 썼는지**로 바꿔 봤다.

| 대각선 | 관측값 | 기준 | 허용치 대비 |
|---|---:|---:|---:|
| 위치 오차 | 4.349 mm | 50 mm | **8.7 %** (여유 많음) |
| 조향 속도 | 1.01415 rad/s | 1.001 rad/s | **101.3 %** (0.0132 rad/s 초과) |

궤적 그래프만 보면 대각선은 깔끔한 직선이고 목표점에 정확히 도착한다. 그래프 제목에 FAIL 이 붙어 있지 않으면
아무도 모를 실패다. **합격은 기준 전체의 AND** 라서, 위치가 아무리 좋아도 한 항목이 1.3 % 넘치면 FAIL 이다.
그리고 기준을 1.02 로 느슨하게 해서 PASS 로 바꾸는 건 하지 않는다. 1.001 이라는 숫자는 1 rad/s 제한에 0.1 %
수치 여유를 준 것이지, 조정하라고 남겨 둔 값이 아니다.

회전도 PASS 지만 yaw 오차가 4.707° 로 기준 5° 의 94 % 를 썼다. 여유 0.29° 다. PASS 들 중에도 여유가 큰 것과 거의
없는 것이 섞여 있어서, 다음 실험에서 무언가를 바꿨을 때 먼저 넘어갈 후보는 회전이다.

### 횡이동이 더 많이 꺾는데 왜 대각선이 넘쳤나

이게 제일 이상했다. 조향 각도로 보면

```text
횡이동 : 0 → 90° (1.571 rad)
대각선 : 0 → 45° (0.785 rad)
```

횡이동이 두 배를 꺾는데 최대 조향 속도는 0.9016 으로 더 낮고, 대각선이 1.0142 로 더 높다. 1 rad/s 로 꺾는다면
횡이동도 최소 1.57 s, 대각선은 0.79 s 가 걸린다. 그러니 "많이 꺾어서 빨라졌다"는 설명은 안 맞는다. 슬라이드는
원인을 말하지 않고, 30장의 다음 실험이 **조향 목표의 변화율을 줄이고 재시험**하는 것이다. 목표 각도가 계단처럼
바뀌면 제어기가 그 순간 크게 반응하는데, 대각선에서 그 순간이 겹치는 방식이 다르다고 짐작만 하고 있다. 확인은
조향 목표와 실제 조향 각속도를 시간축으로 같이 그려 봐야 한다.

## 10. 순간 초과는 녹화에서 안 보인다

28장 오류 표의 마지막 줄이 "기록은 정상인데 순간 초과 발생 → **다운샘플 전 모든 step 최대값**"이다.

검증 영상은 40 s, 25 fps, 1,000 프레임이다. 물리는 $dt = 0.002$ s 니까 500 Hz.

```text
500 Hz / 25 fps = 20 스텝마다 한 프레임
```

19스텝은 영상에 안 남는다. 40 ms 보다 짧게 튀는 조향 속도는 영상이나 다운샘플한 CSV 에서는 정상으로 보일 수 있다.
그래서 속도·토크 최대치는 **모든 physics step** 에서 모은 값으로 판정한다. 이 Isaac 영상도 PhysX CSV 를 MuJoCo
렌더러로 재생한 것이라 재생 중에 동역학을 다시 계산하지 않는다. 영상은 설명용이고 판정은 로그다.

토크 쪽도 비슷한 함정이 있다. 기준은 최종 토크 ≤ 1.000001 N·m 인데, 제어기가 계산한 토크에 **감쇠 항을 더한 뒤**
clip 하지 않으면 최종 적용 토크가 한계를 넘는다. CSV 의 `tau` 열은 감쇠 전 토크라서 그 열만 보고 판정하면 안 된다.

## 13. 막혔던 지점 / 메모

- **정적 PASS 와 주행 PASS 는 다른 말이다.** `physics_runtime=NOT_EXECUTED` 처럼 무엇을 안 했는지 이름에 적어 두는
  습관이 좋아 보였다.
- **USD 는 degree, URDF 는 radian.** 파서는 둘 다 경고 없이 읽기 때문에 형식 간 비교가 아니면 못 잡는다.
- **쿼터니언 순서**: USD 는 wxyz, SciPy 는 xyzw.
- **축 부호는 0 rad 에서 안 보인다.** ±0.3 rad 양쪽을 봐야 한다.
- **그래프가 깔끔해도 FAIL 일 수 있다.** 판정은 로그의 최대값으로 하고, 최대값은 다운샘플 전 모든 step 에서 모은다.
- 4 kg 은 가정값이고 실물 강도·체결은 이 수업의 검증 범위 밖이다.
