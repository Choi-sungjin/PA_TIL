# 2026-09-21 TIL — 굽기 전에 적어 넣은 값이 나중에 들어갈 유일한 문이었다

> 오후 내내 보조컴퓨터 한 대를 세웠다. SD 카드에 OS 를 굽고, 전원을 넣고, 이름으로 찾아 들어가고, 원격 편집기까지 붙이는 것이 오늘 실습이었다. 화면만 따라가면 끝나는 일처럼 보였는데 해보니 아니었다. **이 보드에는 모니터도 키보드도 안 달린다.** 그래서 굽기 전에 설정 화면에 적어 넣은 값이 나중에 이 컴퓨터로 들어갈 수 있는 유일한 통로가 된다. 순서를 그대로 적어두고, 각 단계에서 틀렸을 때 무엇이 되돌아가고 무엇이 안 되돌아가는지를 같이 정리했다.

---

## 1. 왜 보조컴퓨터부터 세워야 했나

Lv.2 과제 구성이 바뀌었다. 지금까지는 **PC 와 제어보드를 USB 로 직접 잇고** 시리얼 모니터로 값을 주고받았는데, 이번 과제는 **보조컴퓨터와 제어보드를 잇고** PC 는 그 보조컴퓨터에 원격으로 붙는 구조다.

```text
지금까지 :  PC ── USB ── 제어보드 ── 모터
이번 과제 :  PC ── 네트워크 ── 라즈베리파이 ── USB ── 제어보드 ── 모터
```

중간에 한 칸이 끼었을 뿐인데 할 일이 달라진다. 그 한 칸이 **스스로 부팅하고 스스로 네트워크에 붙는 컴퓨터**라서, 과제를 시작하기 전에 먼저 그 컴퓨터를 세워야 한다. 오늘 오후 목표도 딱 거기까지였다 — **OS 굽기 → 이름으로 찾기 → 원격 접속.**

## 2. 순서와, 되돌리는 비용

받은 이미저는 `v2.0.11.1` 이고 설치 파일이 $21.5\,\mathrm{MiB}$ 다. 순서를 표로 먼저 적어둔다.

| # | 단계 | 여기서 정하는 것 | 틀렸을 때 |
|---|---|---|---|
| 1 | 장치 | 보드 모델 | 다시 고르면 된다 |
| 2 | 운영 체제 | Ubuntu **Server** 22.04 | 다시 고르면 된다 |
| 3 | 저장소 | 리더기에 꽂은 SD 카드 | 카드가 안 뜨면 리더기부터 본다 |
| 4 | 사용자 지정 | 호스트 이름 · 지역화 · 사용자 · Wi-Fi | **카드를 다시 구워야 한다** |
| 5 | 원격 접근 | SSH 사용 **켜기** | 〃 |
| 6 | 쓰기 → 안전하게 제거 | — | 그냥 뽑으면 쓰다 만 카드가 된다 |
| 7 | 장착 → 전원 → 2분 대기 | — | LED 가 안 깜빡이면 굽기부터 다시 |

표에서 중요한 건 **카드를 다시 구워야 되돌아가는 단계가 4·5 번뿐**이라는 것이다. 1~3번은 화면에서 다시 고르면 그만이지만, 4·5번은 이미 카드에 써진 뒤라 뽑아서 처음부터 해야 한다.

고르는 이미지가 **서버 판**인 것도 같은 이유다. 데스크톱 판은 화면이 있어야 쓸 수 있는데 이 보드에는 그 화면이 없다. 화면이 없는 컴퓨터를 고른 순간부터 **모든 조작은 네트워크로만 들어간다**는 전제가 생긴다.

## 3. 사용자 지정 네 칸이 각각 나중에 무엇이 되는가

이 단계가 오늘의 핵심이었다. 네 칸을 그냥 빈칸 채우듯 넘기면 안 되는 이유가 각각 있었다.

| 칸 | 지금 넣는 것 | 나중에 이게 무엇이 되는가 |
|---|---|---|
| 호스트 이름 | 로봇 번호 | **이 보드를 찾는 주소 대용** |
| 지역화 | 수도 도시 | 시간대와 키보드 배열이 따라 정해진다 |
| 사용자 | 계정 이름 · 비밀번호 | 접속할 때 쓰는 계정 그 자체 |
| Wi-Fi | SSID · 비밀번호 | 부팅하자마자 붙을 망 |

**호스트 이름** 칸에 적힌 안내가 먼저 눈에 띄었다 — 네트워크에서 이 보드를 식별하는 고유한 이름이고, 영문자·숫자·하이픈만 쓸 수 있다. 고유해야 한다는 조건이 왜 붙었는지는 7절에서 실제로 걸렸다.

**지역화**는 수도 도시 하나만 고르면 시간대와 키보드 배열이 따라 채워졌다. 서울을 고르니 시간대가 `Asia/Seoul`, 키보드가 `kr` 로 자동으로 들어갔다. 칸이 세 개인데 실제로 정하는 건 한 개다.

**Wi-Fi** 칸은 **지금 내 노트북이 붙어 있는 망이 자동으로 채워져 있었다.** 편한데, 뒤집어 보면 이 칸은 보드의 고정 설정이 아니라 **내 PC 의 현재 상태를 베껴 넣는 칸**이다. 보안 네트워크 / 공개 네트워크 탭이 따로 있고 숨겨진 SSID 체크박스도 있는데, 지금은 자동으로 채워진 값을 그대로 쓰면 됐다. 다만 나중에 실습망이 분리되면 **그때 다시 설정해야 한다**고 했다. 즉 이 칸은 한 번 정하면 끝나는 값이 아니다.

## 4. SSH 는 기본이 꺼짐이다

원격 접근 칸은 처음 열었을 때 **토글이 꺼져 있고 그 아래 인증 방식(비밀번호 / 공개 키)이 회색으로 잠겨 있다.** 토글을 켜야 아래가 풀린다.

이 칸이 4·5번 중에서도 제일 위험한 칸이다. **안 건드리면 반드시 꺼진 채로 구워지기 때문이다.** 화면도 키보드도 없는 보드에 SSH 가 꺼진 채 구워지면 전원을 넣어도 들어갈 방법이 없다. 부팅은 멀쩡히 되는데 접근만 안 되는 상태가 된다.

다행히 쓰기 직전 요약 화면이 이 셋을 다시 확인해준다.

```text
사용자 계정이 설정되었습니다
Wi-Fi 가 설정되었습니다
SSH 가 활성화되었습니다
```

**이 세 줄이 다 떠 있는지 보고 쓰기를 눌렀다.** 여기서 한 줄이 비어 있으면 뒤로 가서 채우면 되고, 굽고 나서 알면 처음부터다. 요약 화면을 확인 절차로 쓸 수 있다는 걸 이번에 알았다.

## 5. 쓰기가 끝난 것과 디스크에 내려간 것은 다르다

실제로 쓰기 단계에서 한 번 막혔다.

```text
디스크에 파일을 쓰는 동안 액세스 거부 오류가 발생했습니다.
디스크가 쓰기 방지되었거나 다른 애플리케이션에서 사용 중일 수 있습니다.
```

카드가 다른 프로그램에 잡혀 있으면 이렇게 된다. 잡고 있던 쪽을 풀고 다시 썼다.

뽑을 때도 같은 얘기가 나왔다 — **"안전하게 제거할 수 있습니다" 가 떴을 때만 뽑는다.** 리눅스에서는 파일 관리자에서 카드를 우클릭해 마운트를 해제하고 뽑는다. 그냥 뽑으면 아직 안 써진 내용이 날아가서, 보기에는 다 구워진 카드가 실제로는 덜 구워진 카드가 된다.

**쓰기 명령이 끝난 것과 디스크에 실제로 내려간 것이 다르다**는 게 이 두 가지의 공통점이다. 오류 화면이 뜬 쪽은 그나마 낫고, 조용히 안 써진 쪽이 더 나쁘다.

## 6. 부팅은 불빛으로 확인한다

카드를 보드 뒤에 꽂고 전원을 넣으면 전원 표시는 바로 들어온다. 하지만 그건 **전기가 들어왔다는 것뿐이고 OS 가 떴다는 뜻이 아니다.**

읽기 시작하면 초록색 LED 가 깜빡이기 시작한다. **2분쯤 여유 있게 기다리면** 깜빡임이 빨라지고, 그게 부팅이 진행 중이라는 신호다. 화면이 없으니 부팅 과정을 볼 방법이 이것뿐이다.

전원은 제어보드 배터리를 물릴 필요 없이 **휴대폰 충전기로 보드만 띄워도** 된다. 제어보드에 물려두면 배터리가 빨리 닳으니 보드만 시험할 때는 그게 낫다고 했다. **오늘은 실제로 보드만 단독으로 띄웠고 제어보드는 물리지 않았다** — 잇는 건 내일부터다. 랜선을 쓰면 랜 포트 쪽에도 초록 불이 들어와서 연결 상태를 같은 방식으로 볼 수 있다.

## 7. 주소는 부팅마다 바뀌고, 변하지 않는 건 내가 적어 넣은 이름이다

부팅이 됐어도 **들어갈 수가 없다.** 주소를 모르기 때문이다. 게다가 이 주소는 공유기가 그때그때 빌려주는 값이라 **켤 때마다 바뀐다.**

그래서 주소 대신 이름으로 찾는다. 3절에서 적어 넣은 호스트 이름 뒤에 `.local` 을 붙여 ping 을 날렸다.

```text
> ping pa<번호>.local -4

Ping pa<번호>.local [10.2.12.x] 32바이트 데이터 사용:
10.2.12.x의 응답: 바이트=32 시간=192ms TTL=64
10.2.12.x의 응답: 바이트=32 시간=4ms   TTL=64
10.2.12.x의 응답: 바이트=32 시간=5ms   TTL=64
```

응답이 오면서 **주소를 같이 알려준다.** 변하는 값(주소)을 변하지 않는 값(이름)으로 조회하는 구조다.

두 가지를 여기서 배웠다. 첫째, **같은 조회가 한 번에 안 됐다.** PowerShell 에서 날린 건 응답이 없었고, 명령 프롬프트에서 `-4` 를 붙여 날리니 바로 붙었다. `-4` 는 IPv4 로 강제하는 옵션인데, **쉘이 갈랐는지 옵션이 갈랐는지는 확인 못 했다.** 다만 이름이 안 잡힌다고 보드부터 의심하기 전에 **조회하는 쪽을 먼저 바꿔볼 것.**

둘째, **첫 응답만 $192\,\mathrm{ms}$ 고 그다음은 $4 \sim 5\,\mathrm{ms}$ 다.**

```text
192 ms / 4 ms = 48 배
```

같은 장비까지의 왕복 시간이 48배 차이 날 리는 없으니, 첫 패킷에만 붙은 시간은 **이름을 주소로 바꾸는 데 든 시간**이라고 읽었다. 조회가 한 번 끝나면 그다음부터는 주소로 바로 간다.

그리고 여기서 오늘 제일 쓸모 있는 걸 알았다. 이 보드는 **기본 호스트 이름이 다 똑같다.**

```text
같은 이름을 쓰는 장비 24 대가 동시에 켜져 있을 때
내가 부른 이름에 응답한 장비가 내 것일 확률 = 1 / 24 = 4.17 %
```

계정과 비밀번호까지 기본값이면 **남의 보드에 그냥 들어가진다.** 들어가서 뭘 고치면 그건 남의 과제를 망가뜨리는 것이다. 호스트 이름을 로봇 번호로 바꾸라는 지시가 편의가 아니라 **충돌 회피**였다.

주소를 받은 뒤는 전에 해본 SSH 와 같다. 계정과 주소를 주고 붙으면 처음 한 번은 호스트 키를 확인하느냐고 묻고, 수락하면 알려진 호스트 목록에 등록된다. 그다음 비밀번호를 넣으면 들어간다.

## 8. 들어가서 처음 본 화면이 이 보드의 상태표였다

접속하자마자 뜬 요약이 생각보다 많은 걸 알려줬다.

```text
System load: 1.77          Temperature: 43.8 C
Usage of /: 19.0% of 14.06GB   Processes: 153
Memory usage: 6%           Users logged in: 0
Swap usage: 0%             IPv4 address for wlan0: ...

256 updates can be applied immediately.
194 of these updates are standard security updates.
```

주소가 `wlan0` 에 붙어 있다는 것부터가 **3절의 Wi-Fi 칸이 실제로 먹혔다는 확인**이다. 유선이 아니라 무선으로 올라왔다.

용량을 계산해봤다.

```text
14.06 GB x 19.0%  = 2.67 GB   (지금 쓰는 양)
14.06 - 2.67      = 11.39 GB  (남는 양)
194 / 256         = 75.8 %    (보안 업데이트 비중)
```

**서버 판이라 기본 설치가 $2.67\,\mathrm{GB}$ 밖에 안 된다.** 앞으로 여기에 git·ROS·파이썬 패키지가 들어갈 텐데, 쓸 수 있는 건 $11.39\,\mathrm{GB}$ 다. 메모리는 $6\%$ 만 쓰고 있다. 이 두 숫자를 기억해두면 나중에 뭘 올렸을 때 얼마나 먹는지 비교할 수 있다.

살아 있는지 확인하는 방법도 배웠다. **패키지 목록 갱신 명령을 한 번 돌리고 초록 LED 가 바빠지는지 본다.** 그 명령이 디스크에 목록을 쓰기 때문에, 읽기·쓰기가 실제로 도는지를 불빛 하나로 확인할 수 있다. 계측기가 없을 때 쓸 수 있는 가장 싼 계측기다.

패키지 설치 자체는 오늘 일부러 안 했다. **24명이 동시에 받으면 서버가 버티지 못한다**고 해서 git·ROS 설치는 내일로 미뤘다. 보드 한 대짜리 작업이 아니라 24대짜리 작업이라는 게 여기서도 나온다.

## 9. 원격 편집기는 보드에 서버를 심는 일이었다

마지막으로 편집기에서 원격 접속을 걸어봤다. 나는 이걸 "화면만 빌려 쓰는 것" 정도로 알고 있었는데, 붙는 동안 나온 로그가 그게 아니라고 말했다.

```text
osReleaseId    == ubuntu
arch           == aarch64      (보드 쪽 CPU)
vscodeArch     == arm64
downloadTime   == 3609
installTime    == 500
serverStartTime == 159
```

즉 접속할 때 **보드의 CPU 종류를 알아내서 거기 맞는 서버를 내려받고, 보드 안에 설치하고, 그 위에서 띄운다.** 내 노트북은 그 서버에 붙는 것뿐이다.

```text
3609 + 500 + 159 = 4268 ms = 4.27 초  (첫 접속에 든 시간)
```

$4.3$ 초가 걸린 이유가 이거였고, 두 번째 접속부터 빠른 이유도 같다 — 이미 심어놨기 때문이다.

8절에서 본 메모리 $6\%$ 와 남은 용량 $11.39\,\mathrm{GB}$ 가 여기서 의미가 생긴다. **원격 편집기를 켜는 것 자체가 보드의 메모리와 디스크를 먹는다.** 제어 루프가 도는 보드에서 이걸 켜놓는 건 공짜가 아니다. 붙이는 방법은 여러 개(WSL·호스트·터널·컨테이너)인데 오늘 쓴 건 SSH 로 호스트에 붙는 것이고, 한 번 붙이면 호스트 목록에 등록돼 다음부터는 고르기만 하면 된다.

## 11. 막혔던 지점 / 메모

- **이름 조회가 한 번에 안 됐다.** PowerShell 쪽은 응답이 없었고, 명령 프롬프트에서 `-4` 를 붙인 쪽은 바로 붙었다. 쉘과 옵션이 동시에 달라져서 **무엇이 갈랐는지 모른다.** 내일 하나씩만 바꿔가며 다시 볼 것. 그 전까지는 **보드가 죽었다고 판단하기 전에 조회하는 쪽부터 바꿔본다**만 남겨둔다.
- **첫 핑이 48배 느린 이유는 내 해석이다.** 이름을 주소로 바꾸는 시간이라고 읽었지만, 부팅 직후라 보드 쪽이 바빴을 가능성도 있다. 내일 다시 켜서 한 번 더 재볼 것.
- **호스트 이름을 계정 이름과 같게 하라고 했다.** 따로 두면 접속할 때 둘 다 기억해야 하는데, 원격 접속은 계정과 주소를 같이 넣어야 해서 하나를 잊으면 못 들어간다. 편의 같지만 **기억해야 할 값의 개수를 줄이는** 얘기였다.
- **기록에 남기면 안 되는 값이 많았다.** 설명 중에 계정 이름·비밀번호·SSID·장비 주소·호스트 키 지문이 다 화면에 나왔다. 이 저장소는 공개라서 계정과 비밀번호와 SSID 는 아예 안 적었고, 주소는 `10.2.12.x` 로, 이름은 `pa<번호>` 로만 적었다. **설정 방법은 적되 설정값은 안 적는다.**
- **오늘 실습 목표는 원격 접속까지였고 거기까지 됐다.** 제어보드를 물리고 모터를 돌리는 건 내일부터다. 오늘 세운 게 다음 과제 전체의 전제라서, 여기서 대충 넘어가면 내일 것이 통째로 막힌다.
