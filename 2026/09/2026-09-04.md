## 1. 순서를 바꾸면 같은 점이 14.16도 벌어진다

$R_yR_z \neq R_zR_y$ 는 알고 있었는데 얼마나 다른지는 재본 적이 없었다.

```text
A = R_y(22.5) R_z(67.5)   # z 를 먼저 적용
B = R_z(67.5) R_y(22.5)   # y 를 먼저 적용

max|A - B| = 0.353553
A (1,0,0) = [ 0.353553  0.923880 -0.146447]
B (1,0,0) = [ 0.353553  0.853553 -0.382683]
두 결과 사이 각도 = 14.158401 deg
```

성분 차이 0.354는 감이 안 오는데 **같은 점이 14.16도 떨어진 곳에 도착한다**니 바로 와닿았다. 표기 규칙도 정리됐다 — $R_yR_z\mathbf{p}$ 는 오른쪽이 먼저다. 첫 회전이 두 번째 회전의 축을 이미 움직여 놓으니, 두 순서는 **두 번째 회전이 쓰는 축 자체가 다르다.**

8월 27일부터 "$R_y$ 는 부호 배치가 예외"라고 외워둔 것도 같은 순서 문제였다. 각 회전은 나머지 두 축을 $x\to y\to z\to x$ 로 돌리는데, $R_x$ 는 $(y,z)$, $R_z$ 는 $(x,y)$ 로 첨자가 오름차순인 반면 $R_y$ 가 도는 평면만 $(z,x)$ 라 적을 때 뒤집힌다. **뒤집어 적었으니 전치가 되고, 전치되면 $\sin$ 부호가 반대로 보인다.**

## 2. 직교성만으로는 회전이 아니다

$R^{\mathsf{T}}R=I$ 이면 $\det(R)^2=1$ 이니 행렬식은 $\pm 1$ 뿐이다. $-1$ 인 쪽이 뭔지 대각성분 $(1,-1,1)$ 인 $S$ 로 확인했다.

```text
S^T S = I ?  True
det(S)    =  -1.0
x' x y'   =  [ 0.  0. -1.]      z' = [0. 0. 1.]
```

직교성은 통과하고 길이도 각도도 보존한다. 그런데 **$\mathbf{x}'\times\mathbf{y}'$ 가 $-\mathbf{z}'$** 다. 오른손 좌표계가 왼손으로 뒤집힌 것이고 이건 아무리 돌려도 만들 수 없다 — 거울에 비친 손을 회전으로 겹칠 수 없다는 이야기가 행렬식 한 칸에 들어 있었다. 자세 행렬에 섞이면 카메라가 "오른쪽"이라 준 값이 팔에서 왼쪽이 된다. 8월 19일에는 $\det \to 0$ 만 위험한 줄 알았는데, $\det=-1$ 은 크기가 멀쩡해서 더 조용하다.

## 3. 20만 번 곱하면 회전행렬이 아니게 된다

로봇은 자세를 매 주기 누적 갱신한다. 반올림이 쌓여 직교성이 무너진다는 건 8월 31일에 개념으로 적어뒀는데, 오늘 20만 번을 돌려 크기를 봤다. 지표는 $\varepsilon(R)=\lVert R^{\mathsf{T}}R-I\rVert_F$.

```text
float64  err = 4.211121e-11   det = 1.000000000035
float32  err = 5.061585e-04   det = 1.000109253726
비율 32/64 = 1.20e+07   -> float32 가 약 7자리 나쁘다

열 길이 상대오차 최대     = 1.256021e-04   -> 1m 팔 끝에서 0.13mm
열 사이 각도의 90도 이탈  = 0.014966 deg
```

직교여야 할 축들이 0.015도 기울었다. 근거 없이 생긴 자세 오차다. 랜덤워크 모델 $\sqrt{n}\,\varepsilon_{\mathrm{machine}}\,$ 도 계산해봤는데 **자릿수만 맞고 상수는 안 맞았다** — float64 는 모델 9.93e-14 대비 424배, float32 는 5.33e-05 대비 9.5배였다.

복구는 modified Gram-Schmidt 로 했다. 8월 26일에 만든 `project`/`reject` 를 열마다 반복하는 일이었다.

```text
복구 전 err = 5.061585e-04
복구 후 err = 2.537223e-16      det = 1.0
자세 변화 max|R_fixed - R| = 2.418104e-04
```

마지막 두 줄이 핵심이다. 오차는 12자리 줄었는데 **자세 자체는 0.00024 밖에 안 움직였다.** 재직교화는 자세를 건드리지 않고 어긋난 만큼만 되돌린다는 뜻이다. `np.linalg.qr` 로 대체하면 안 되는 이유도 여기 있다 — QR 은 열 부호를 임의로 뒤집을 수 있어 오차는 0이 되는데 자세가 딴 데로 간다.

## 4. 곱하는 순서를 틀리면 57.8cm 옆을 집는다

어제 남겨둔 좌표 체인을 이어서 봤다. $T^{\mathrm{base}}_{\mathrm{cam}} = T^{\mathrm{base}}_{\mathrm{link}}T^{\mathrm{link}}_{\mathrm{cam}}$ 처럼 첨자가 이웃끼리 상쇄되게 적으면 순서를 안 틀린다는데, 틀렸을 때 손해가 얼마인지 재봤다. link 는 z축 22.5도 회전 후 (0.35, 0.05, 0.45)m, camera 는 y·x 회전 후 (0.12, 0.04, 0.18)m 로 두고 카메라가 본 점 (0.10, 0.05, 0.40)을 base 로 옮겼다.

```text
올바른 순서  p_base = [ 0.594561 -0.184693  0.852367]
뒤집은 순서  p_base = [ 0.339016 -0.693841  0.757263]
두 점 사이 거리 = 0.577563 m

왕복 오차 max|T^-1 T p - p| = 1.110223e-16
```

**57.8cm.** 픽앤플레이스에서 이 정도면 물건이 아니라 옆 선반을 집는다. 더 나쁜 건 두 결과 다 그럴듯한 좌표라 값만 보고는 틀린 걸 알 수 없다는 점이다. 9월 2일에 만든 `inv_T` 로 왕복시켜 $10^{-16}$ 이 나오는지 보는 게 유일한 검사였다.

## 5. 짐벌락을 숫자로 — pitch 90도에서 각이 두 개가 아니다

오늘 본 자료에 짐벌락 그림이 있었다. 8월 19일에 같은 그림을 봤을 때는 "축이 겹친다"까지만 이해했는데, 오늘은 행렬로 확인했다. ZYX 순서 $R=R_z(\alpha)R_y(\beta)R_x(\gamma)$ 에서 $\beta=90^\circ$ 를 넣고 $\alpha-\gamma$ 만 같은 두 조합을 비교했다.

```text
R(30, 90, 10) vs R(50, 90, 30)   # a-g 는 둘 다 20
max 차이 = 1.665335e-16          <- 완전히 같은 행렬

R(30, 90, 10) vs R(30, 90, 40)   # a-g 가 20 vs -10
max 차이 = 0.515668
```

**세 각을 넣었는데 결과가 두 개($\beta$ 와 $\alpha-\gamma$)로만 결정된다.** 자유도 하나가 없어졌다는 게 이 뜻이었고, 링이 겹치는 그림보다 훨씬 분명했다.

역으로 각을 뽑을 때가 더 인상적이었다. 표준 복원식 $\alpha=\mathrm{atan2}\,(R_{21},R_{11})$ 에 들어가는 성분을 찍어봤다.

```text
R[0,0] = 5.303e-17    R[1,0] = 3.062e-17
atan2 로 복원한 alpha = 29.999999999999996
```

30도가 정확히 나왔다. 그런데 이건 맞은 게 아니라 **$10^{-17}$ 짜리 반올림 찌꺼기 둘의 비를 잰 것**이다. $10^{-9}$ 노이즈를 얹으니 alpha 는 30.0000 → 72.0491, gamma 는 10.0000 → −93.0411 로 튀었다. 센서 잡음보다 훨씬 작은 값에 각이 40도, 100도씩 움직인다. 어제 축·각 복원에서 $\theta$ 가 0이나 $\pi$ 근처면 부호가 무너진다고 적었는데, **같은 종류의 특이점이 오일러 각에도 있고 그쪽이 훨씬 자주 걸린다.** pitch 90도는 로봇 팔에서 흔한 자세다.

## 6. 쿼터니언이 이기는 자리와 지는 자리

자료에는 쿼터니언 장점으로 "숫자 4개 vs 행렬 9개, 100만 점 최적화"가 적혀 있었다. 뒤가 걸려서 축 $\mathbf{k}=(1,2,2)/3$, 67.5도로 만든 단위 쿼터니언으로 100만 점을 돌려봤다.

```text
q = [0.831470  0.185190  0.370380  0.370380]   |q| = 1.0
쿼터니언 -> 행렬 변환이 로드리게스와 일치: 차이 0.0

행렬 곱 (P @ R.T)        0.0049 s
쿼터니언 샌드위치 공식    0.0944 s   -> 19.07배 느림
두 결과 차이 = 1.78e-15
```

**점을 많이 돌리는 일에서는 행렬이 압도적으로 빠르다.** 점 하나당 행렬은 곱셈 9번인데 샌드위치 공식은 내적·외적이 따로 들어가 두 배 넘게 든다.

| 하는 일 | 유리한 쪽 |
|---|---|
| 자세를 저장·전송 | 쿼터니언 (4개 vs 9개) |
| 자세를 계속 누적 합성 | 쿼터니언 (정규화가 나눗셈 한 번) |
| 두 자세 사이 보간 | 쿼터니언 (SLERP, 행렬은 방법이 없다) |
| 점 100만 개를 돌리기 | 행렬 (19배) |

3절과 나란히 놓으니 분명해졌다. 회전행렬을 제자리로 돌리려면 Gram-Schmidt 를 돌려야 하는데 **쿼터니언은 길이로 나누기 한 번이면 끝난다.** 9개짜리에 걸린 제약(직교 6개 + $\det=+1$)이 4개짜리에서는 $\lVert q\rVert=1$ 하나로 줄기 때문이다. 실전 순서는 "누적은 쿼터니언으로, 쓰기 직전에 행렬로" — 모듈 ④가 상호 변환을 둘 다 요구하는 이유가 이거였다.

## 8. 막혔던 지점 / 메모

- **성분 차이는 감이 안 온다.** $\max|A-B|=0.354$ 보다 "같은 점이 14.16도 벌어진다"가 훨씬 쓸모 있었다. 앞으로는 대표점 하나를 통과시켜 보기로 했다.
- **$\det=-1$ 은 $\det\to 0$ 보다 조용하다.** 크기가 1이라 노름이나 조건수로는 안 걸리니, 외적으로 오른손 규칙을 확인하는 검사가 따로 있어야 한다.
- **$\sqrt{n}\varepsilon$ 은 자릿수 눈금이지 예측값이 아니다.** 안전 여유를 모델값으로 잡으면 안 된다.
- **atan2 가 정답을 줘도 믿으면 안 된다.** 짐벌락에서 30도가 정확히 나왔지만 입력은 $10^{-17}$ 짜리 잡음 둘이었다. 값이 맞았는지가 아니라 **입력 성분의 크기**를 봐야 한다.
- **자료의 주장을 재보길 잘했다.** "100만 점 최적화"가 쿼터니언 장점으로 적혀 있었는데 실제로는 행렬이 19배 빨랐다. 쿼터니언의 이득은 저장·누적·보간이지 대량 점 변환이 아니다.
- 배포본을 아직 제출 저장소로 안 옮겼다. `physicalai-lv1-<이름>` 을 만들고 `lv1_module3/` 로 복사해서 시작해야 한다.
