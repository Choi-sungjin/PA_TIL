# 2026-09-10 TIL — nan은 입구에서 잡고, 커널은 재시작해서 믿는다

> 코드를 새로 배운 날이 아니라 **틀어진 상태를 어떻게 드러내는가**를 배운 날이다. 오전에는 Jupyter 커널이 화면과 다른 순서를 기억하고 있다는 걸 실험으로 확인했고, 오후에는 영벡터·일직선 같은 퇴화 입력을 만나면 어떻게 할지를 **정책으로 선언하고 검증까지** 붙였다. 9월 3일에 "조용히 실패하는 것들"을 적었는데, 오늘은 그 조용함이 계산 결과 안에서 번지는 쪽이었다.

## 1. 화면 순서는 실행 순서가 아니다

노트북에 셀 세 개를 두고 직접 실험했다.

```text
[실험 A] count = 0        → 출력 count = 0
[실험 B] count = count+1  → 두 번 실행       → 출력 count = 3
[실험 C] print(count)
```

A 한 번, B 두 번을 돌리면 C 에서 3이 나온다. 화면상 B 는 한 칸인데 값은 2가 올라갔다. **커널은 셀의 화면 위치가 아니라 실제 실행 순서를 기억하기 때문**이다.

그다음이 핵심이었다. 커널을 재시작하고 **C 만** 실행하면

```text
NameError: name 'count' is not defined
```

같은 노트북, 같은 화면인데 결과가 다르다. 셀 왼쪽의 실행 번호 `[n]` 이 화면 순서와 어긋나 있는 게 유일한 단서였다.

## 2. 그래서 제출 전 재시작이 규칙이다

이게 왜 규칙인지 이제 알겠다. 내 화면에서는 잘 돌아간다 — **이미 메모리에 값이 올라가 있으니까.** 채점하는 쪽은 노트북 파일만 받아 새 커널에서 여는데, 그때는 그 값이 없다.

`Kernel → Restart Kernel and Run All Cells` 는 편의 기능이 아니라 **의존성이 위에서 아래로만 흐르는지 검증하는 절차**였다. 통과하면 "이 노트북은 순서대로 읽어도 재현된다"가 보장된다.

같은 이유로, 노트북을 돌리는 동안 **같은 소스를 쓰는 다른 노트북이나 pytest 를 동시에 돌리지 않기로** 했다. 특히 모듈 3 문제 3은 실험이 소스를 잠시 고쳤다가 `finally` 에서 복구하는 구조라, 그 사이에 다른 프로세스가 읽으면 망가진 버전을 본다. 9월 3일에 `try`/`finally` 로 원본을 되돌리는 걸 배웠는데, 그 복구가 **원자적이지 않다**는 게 오늘 붙은 조건이다.

## 4. 영벡터를 길이로 나누면

정규화는 $\hat{v} = v / \lVert v \rVert$ 인데, $v$ 가 영벡터면 분모가 0이다. 보호 장치 없이 그냥 나눠보고 무엇이 나오는지 기록하는 게 오늘의 과제였다.

```text
영벡터 / 노름  ->  [nan nan nan]
raw + 1        ->  [nan nan nan]
raw[0] == raw[0]  ->  False
```

$0/0$ 은 예외가 아니라 **`nan` 이라는 값**으로 나온다. 경고 한 줄이 뜰 뿐 프로그램은 멈추지 않는다. 그리고 세 가지가 이어졌다.

- **nan 은 전염된다.** 이후 모든 연산에 그대로 번진다.
- **nan 은 자기 자신과도 같지 않다.** `nan == nan` 이 `False` 다. 그래서 `==` 로 하는 검사는 nan 을 잡지 못하고, `np.isnan` 을 써야 한다.
- 그래서 `assert raw[0] == raw[0]` 같은 검사가 조용히 실패한다.

**틀린 값이 아니라 "값 아님"이 계산 전체에 퍼지는데, 아무도 멈추지 않는 상태.** 9월 3일의 QoS 경고 0개와 같은 종류의 침묵이다.

## 5. 정책을 선언하고, 검증까지 붙인다

과제가 요구한 게 좋았다. "알아서 처리하라"가 아니라 **어떻게 처리할지 직접 정하고 그 근거를 적으라**는 것이었다. 선택지는 둘이다.

| 정책 | 동작 |
|---|---|
| `raise` | 크기가 허용오차 이하면 `ValueError` 를 던진다 |
| `zero` | 영벡터를 그대로 돌려준다 |

`raise` 를 골랐고 근거는 이렇게 적었다 — **잘못된 방향값을 조용히 전파하는 것보다 입력 지점에서 원인을 명확히 드러내는 편이 안전하다.** nan 이 열 줄 뒤에서 터지면 원인을 거슬러 올라가야 하지만, 입구에서 막으면 어느 입력이 문제였는지가 그 자리에 남는다.

중요한 건 **선택을 코드에 상수로 박아두고 검증 셀이 그 상수를 읽는다**는 구조였다.

```python
ZERO_POLICY       # "raise" | "zero"
DEGENERATE_POLICY # "raise" | "zero"
```

검증 셀이 "정책이 raise 면 ValueError 가 났는가, zero 면 영벡터가 나왔는가"를 확인한다. 어느 쪽을 골라도 통과하되, **고른 것과 구현이 일치해야만** 통과한다. 정답을 하나로 정하지 않고 일관성을 채점하는 방식이 인상적이었다.

## 6. 일직선 세 점도 같은 문제였다

평면의 법선을 구하는 함수도 똑같은 구조로 갔다. 세 점이 일직선이면 평면이 하나로 정해지지 않는다 — 퇴화 입력이다.

```text
xy 평면 법선: [0. 0. 1.]
기울어진 평면 법선: [0.428571 0.857143 0.285714]  / 손 계산: [0.428571 0.857143 0.285714]
일직선 입력 처리: ValueError - 세 점이 일직선이어서 평면 법선을 정할 수 없습니다
```

법선 값을 손으로 확인했다. 기대값이 $\pm(3,6,2)/7$ 인데,

```text
|(3, 6, 2)| = sqrt(9 + 36 + 4) = sqrt(49) = 7
(3, 6, 2)/7 = (0.428571, 0.857143, 0.285714)
```

노름이 정확히 7이라 나누면 딱 떨어진다. 화면 값과 여섯 자리까지 같았다.

부호가 $\pm$ 인 것도 짚고 넘어갔다. 외적의 방향은 두 모서리 벡터를 어느 순서로 넣느냐에 따라 뒤집히므로, 검증도 `allclose(nq, expected) or allclose(nq, -expected)` 로 양쪽을 다 받는다. 8월 31일에 회전축 부호가 고유벡터로 정해지지 않는다고 적었는데, 같은 이야기가 여기서도 나왔다.

1-5 검증은 여섯 항목 전부 `[PASS]`, 전체 통과 `True` 였다.

## 7. rank 가 3이 아닌 이유

세 벡터 $(2,1,0)$, $(1,3,1)$, $(3,4,1)$ 을 행으로 쌓은 행렬의 rank 를 구하는 문제인데, 코드를 돌리기 전에 눈으로 보라고 했다. 보니까 바로 나왔다.

```text
(2, 1, 0) + (1, 3, 1) = (3, 4, 1)
```

**세 번째가 앞의 두 개의 합이다.** 새 방향을 하나도 더하지 않으니 세 벡터가 만드는 건 3차원 공간이 아니라 평면이다. 그래서 rank 는 2고, 행렬식은 0이다. 직접 계산해서 확인했다.

rank 를 "선형독립인 행의 개수"이자 "행 사다리꼴로 만들었을 때 살아남는 피벗의 개수"로 정리했다. 8월 26일에 `1-6` 을 처음 볼 때는 rank 가 왜 3이 아닌지 몰라 넘어갔는데, 오늘은 숫자를 더해보는 것으로 끝났다.

## 9. 막혔던 지점 / 메모

- **`nan == nan` 은 False 다.** 그래서 `==` 나 `assert` 로는 nan 을 못 잡는다. `np.isnan` 을 써야 한다. 이걸 모르면 검사를 넣고도 통과했다고 착각한다.
- **`0/0` 은 예외가 아니라 값이다.** 경고만 뜨고 계속 흐른다. 보호 장치를 넣는 자리는 나눗셈 직전이다.
- **venv 를 만드는 것과 Jupyter 커널로 등록하는 것은 별개다.** `ipykernel install` 을 빼먹으면 목록에 뜨지도 않는다.
- **커널 이름만 믿지 말고 `sys.executable` 을 볼 것.** 엉뚱한 인터프리터로 돌아도 화면상으로는 구분이 안 된다.
- **`finally` 복구는 원자적이지 않다.** 소스를 잠시 고쳤다 되돌리는 실험이 도는 동안 다른 프로세스가 그 파일을 읽으면 망가진 버전을 본다. 그 시간대에는 같은 소스를 쓰는 pytest 를 돌리지 않는다.
- **법선의 부호는 모서리 벡터 순서가 정한다.** 검증은 $\pm$ 양쪽을 다 받아야 한다.
- 정책을 상수로 선언하고 검증이 그 상수를 읽는 구조가 좋았다. 정답을 하나로 못 박지 않으면서 **고른 것과 구현이 어긋나면 잡아낸다.**
- 오늘 화면 녹화 여섯 개 중 세 개에만 소리가 있었고(29분·50분·62분), 나머지 셋은 무음이었다. 이 노트는 화면을 읽어 정리한 것이라 말로 오간 내용은 빠져 있다.
