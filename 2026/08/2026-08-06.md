# 5강. Python 프로그래밍

## 1. venv — 프로젝트마다 독립된 패키지 방

시스템 Python에 `pip install`을 남발하면 OS와 ROS2가 쓰는 파이썬이 망가진다.
**시스템 Python은 성역, 작업은 항상 venv 안에서.**

```bash
python3 -m venv .venv              # 생성 (프로젝트당 1회)

source .venv/bin/activate          # 활성화 (Linux/macOS)
# .venv\Scripts\activate           # Windows

pip install numpy matplotlib       # 이 방에만 설치됨
pip freeze > requirements.txt      # 환경 기록 (팀 공유용)

deactivate                         # 나오기
```

활성화되면 프롬프트 앞에 `(.venv)`가 붙는다. 이게 안 붙어 있으면 시스템 파이썬에 설치하고 있는 것.

팀원은 `pip install -r requirements.txt` 한 줄로 같은 환경을 재현한다. **"내 컴퓨터에선 되는데요"의 상당수가 이 절차 하나로 예방된다.**

## 4. 셀은 독립적이지 않다

셀은 각각 독립된 프로그램이 아니라 **같은 커널 메모리를 이어서 건드리는 조각**이다.

## 5. 자료구조 — 뭘 언제 쓰나

| 상황 | 자료구조 |
|---|---|
| 순서 있는 목록, 추가/삭제 잦음 | `list` |
| 바뀌면 안 되는 값 묶음 | `tuple` |
| 이름(키)으로 조회 | `dict` |
| 중복 제거 · 소속 검사 | `set` |

```python
distance_log = []                 # list — 시계열 누적
distance_log.append(0.83)

home_position = (0.0, 0.0, 0.0)   # tuple — 불변. 실수로 바꾸면 TypeError로 막아줌

sensor_values = {"lidar": 0.83, "imu_pitch": 2.1}   # dict — O(1) 조회

detected_ids = {3, 7, 12}         # set
if 7 in detected_ids:             # O(1). list였다면 O(n)
    ...
```

### 시간 복잡도

| 연산 | list | dict / set |
|---|---|---|
| 끝에 추가 | O(1) | O(1) |
| 인덱스 접근 | O(1) | — |
| **포함 검사 `x in a`** | **O(n)** — 전부 뒤짐 | **O(1)** — 해시로 즉시 |
| 중간 삽입/삭제 | O(n) | O(1) |

dict/set은 내부적으로 **해시 테이블**을 써서 "몇 번째 서랍인지"를 바로 계산한다. 그래서 크기와 무관하게 빠르다.

**실전 함정:** 30Hz 루프 안에서 누적되는 ID 목록에 `if x in ids:`를 `list`로 하면, 처음엔 잘 돌다가 데이터가 쌓일수록 마감을 놓치는 **성능 버그**가 된다. → `set`으로 바꾼다.

노트북에서 `%timeit x in my_list`로 그 자리에서 직접 잴 수 있다.

## 6. 가변 기본 인자 함정

```python
def add(v, log=[]):    # ❌
    log.append(v)
    return log

print(add(1))   # [1]
print(add(2))   # [1, 2]  ← 초기화 안 됨!
```

기본값 리스트가 **함수 정의 시점에 한 번만** 만들어져서 호출 간에 공유된다. 해결:

```python
def add(v, log=None):   # ✅
    if log is None:
        log = []
    log.append(v)
    return log
```

## 7. 객체지향 — 상속과 다형성

```python
class Sensor:
    def __init__(self, name: str, port: str):
        self.name = name
        self.port = port
        self.is_connected = False

    def read(self):
        raise NotImplementedError    # 자식이 반드시 구현

class Lidar(Sensor):
    def read(self) -> list[float]:   # 오버라이드
        return [0.8, 0.82, 0.85]

class Imu(Sensor):
    def read(self) -> dict[str, float]:
        return {"pitch": 2.1, "roll": -0.3}

# 다형성 — 타입을 몰라도 동일하게 다룬다
sensors: list[Sensor] = [Lidar("front", "/dev/lidar"), Imu("body", "/dev/imu")]
for s in sensors:
    print(s.name, s.read())          # 같은 호출, 다른 동작
```

**이 패턴의 진짜 힘은 확장에서 나온다.** 초음파 센서가 추가돼도 `Sensor`를 상속한 클래스 하나만 만들면 위 루프는 한 줄도 안 바뀐다.

ROS2의 `class MyNode(Node):`도 정확히 이 구조.

### 매직 메서드

```python
class Vector2:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, o):  return Vector2(self.x + o.x, self.y + o.y)   # v1 + v2
    def __abs__(self):     return (self.x**2 + self.y**2) ** 0.5        # abs(v)
    def __repr__(self):    return f"Vector2({self.x:.2f}, {self.y:.2f})"  # print(v)
```

`__init__`, `__repr__`, `__add__`, `__eq__`, `__len__` 정도만 알아도 실전 코드는 대부분 읽고 쓸 수 있다.

### 캡슐화

| 이름 | 뜻 |
|---|---|
| `name` | 공개 — 밖에서 써도 됨 |
| `_buffer` | 내부용 — "만지지 마세요"라는 **약속** (강제 아님) |
| `__count` | name mangling — 상속 클래스와 이름 충돌까지 막고 싶을 때 |

파이썬은 접근을 **강제로 막지 않고 이름 규칙으로 의도를 표시**한다.
읽기 전용 계산값은 `@property`로 감싸면 속성처럼 읽히면서 대입은 막힌다.

# 6강. NumPy 벡터 연산

## 1. ndarray가 빠른 이유 = 메모리 구조

- **list**: 포인터들의 목록. 원소가 메모리 여기저기 흩어진 별도 객체 → 반복문이 원소마다 "포인터 추적 + 타입 확인 + 객체 연산"을 반복.
- **ndarray**: **같은 dtype 값이 연속된 한 덩어리** → CPU 캐시에 착착 올라가고, C 내부 루프가 SIMD로 여러 값을 한꺼번에 처리.

100만 원소 곱셈에서 **약 56배** 차이.

> **핵심 규칙: ndarray를 만들어 놓고 Python `for`문으로 원소를 하나씩 돌면 NumPy의 이점이 전부 사라진다.**

## 2. 기본기 — shape · dtype · axis

```python
import numpy as np

a      = np.array([0.8, 0.82, 0.85, 0.79])
scan   = np.zeros(360)                       # LiDAR 1회전
angles = np.linspace(0, 2*np.pi, 360)        # 0~2π 균등 분할
img    = np.random.rand(480, 640, 3)         # RGB 이미지

a.shape      # (4,)
img.shape    # (480, 640, 3)
a.dtype      # float64  ← 원소 전부 동일 타입
img.ndim     # 3
```

로봇 데이터의 전형적 shape:

| 데이터 | shape |
|---|---|
| LiDAR 1스캔 | `(360,)` |
| 위치 궤적 | `(N, 3)` |
| 회전 행렬 | `(3, 3)` |
| 컬러 이미지 | `(H, W, 3)` |

### axis 읽는 법

**`axis=k`는 "k번째 차원을 붕괴시킨다"로 읽으면 안 헷갈린다.**

```python
traj.shape           # (3, 3) — 시점 3개 × 좌표 3개
traj.mean(axis=0)    # (3,) — 시점 방향 붕괴 → 좌표별 평균
traj.mean(axis=1)    # (3,) — 좌표 방향 붕괴 → 시점별 평균
```

**결과의 shape를 먼저 떠올리는 습관**이 다차원 사고의 핵심.

### dtype 함정 — 오버플로

`uint8`(0~255) 이미지에서 `250 + 10`이 **4**가 된다. 255를 넘는 순간 한 바퀴 돈다.

```python
img.astype(np.float64)   # 계산 전 승격이 관례
```

> **값이 이상할 때 절반은 dtype 문제.** shape만큼 dtype을 의심할 것.

## 3. 슬라이싱은 복사가 아니라 **뷰(view)**

```python
scan[0:90]       # 전방 90°
scan[::2]        # 한 칸 걸러 다운샘플
img[100:200, 300:400]   # ROI
img[:, :, 0]     # R 채널만 → (480, 640)
img[::2, ::2]    # 해상도 절반
```

### 뷰를 고치면 원본도 바뀐다

```python
roi = img[100:200, 300:400]
roi[:] = 0        # ROI를 칠하면...
                  # img의 그 영역도 같이 검게 변한다! 같은 메모리를 보고 있음

safe = img[100:200, 300:400].copy()   # 독립 사본이 필요하면 .copy()
```

대용량 데이터를 복사 없이 다루는 강력한 기능이지만, 모르면 **"원본이 왜 바뀌지?"** 버그가 된다.
노트북은 셀을 재실행할 때마다 원본이 계속 오염돼서 혼란이 커진다. **의심스러우면 `.copy()`.**

정리하면 — **슬라이스는 뷰(원본 공유), 마스킹·팬시 인덱싱은 복사.**

## 4. 불리언 마스킹 — 벡터화의 꽃

**조건 → 마스크 → 선택**, 이 세 박자가 기본형.

```python
scan = np.array([0.3, 8.2, 0.5, 12.0, 0.45, 9.9])

mask = scan < 1.0          # [True, False, True, False, True, False]
near = scan[mask]          # [0.3, 0.5, 0.45] — 1m 이내만

scan[scan > 10.0] = 10.0   # 최대거리 클리핑

# 복합 조건 — 괄호 필수! and/or 아니고 & / |
valid = scan[(scan > 0.1) & (scan < 10.0)]
```

`and`/`or`가 아니라 `&`/`|`를 쓰고, **연산자 우선순위 때문에 괄호가 필수**다. 이거 빼먹으면 에러난다.

## 5. 브로드캐스팅

shape를 **뒤에서부터** 짝지어 비교해서:
1. 두 크기가 **같거나**
2. 한쪽이 **1**이면 → 호환 (1인 쪽이 상대 크기로 늘어남)

모든 짝이 호환이면 연산 가능. 중요한 건 **이 늘림이 실제 메모리 복사 없이** 일어난다는 것.

```python
A = np.random.rand(480, 640, 3)   # 이미지
m = np.array([0.5, 1.0, 2.0])     # 채널별 계수 (3,)

A * m
# A: (480, 640, 3)
# m: (          3)   ← 뒤에서부터 3=3 ✓
# → R×0.5, G×1.0, B×2.0 이 한 줄로
```

자주 쓰는 패턴:

```python
traj_centered = traj - traj[0]     # ① (N,3) - (3,) 원점 이동

R = np.array([[0,-1,0],[1,0,0],[0,0,1]])   # z축 90° 회전
traj_rot = traj @ R.T                       # ② N개 점을 한 번에 회전!

scan_m = scan_mm * 0.001           # ③ 스칼라 브로드캐스팅
```

②번이 특히 중요. **TF2 좌표 변환과 기구학이 전부 "점들의 배열 × 회전 행렬"**이고, NumPy에서는 반복문 없이 `@` 하나로 끝난다.

## 6. 벡터화 전환 공식

| 반복문 패턴 | 벡터화 대응 |
|---|---|
| 원소마다 계산 | 배열 전체 연산 (`a*2`, `np.sin(a)`) |
| `if`로 걸러서 모으기 | 불리언 마스킹 `a[cond]` |
| `if`로 값 바꾸기 | `np.where(cond, x, y)` 또는 `a[cond] = x` |
| 합·평균·최대 | `.sum()` `.mean()` `.max()` (+ `axis`) |
| 두 배열 짝지어 계산 | 같은 shape 연산 / 브로드캐스팅 |
| 최솟값의 **위치** | `np.argmin` / `np.argmax` |

예시 — "속도가 안전 한도를 넘는 비율":

```python
# ❌ 반복문 사고
count = 0
for v in velocity_log:
    if abs(v) > 1.0:
        count += 1
ratio = count / len(velocity_log)

# ✅ 벡터화 사고
ratio = (np.abs(velocity_log) > 1.0).mean()   # True=1, False=0의 평균 = 비율
```

`True/False`의 평균이 그대로 비율이 된다는 게 깔끔했다.

- 복합 조건 마스킹에서 `and` 쓰면 안 된다. `&`이고 **괄호 필수**.
- 슬라이스는 뷰라서 노트북에서 셀 재실행하다 보면 원본이 조용히 오염된다. 헷갈리면 `.copy()`.
- 각 단계마다 `.shape`를 출력해서 확인하는 습관 — 6강 실습에서 이게 제일 도움됐다.
- 제출 전 `Restart Kernel and Run All Cells` 는 무조건.
