## 1. 과제의 뼈대 — 만들고, 검증까지 한다

`01_vectors.ipynb` 에서 함수 열두 개를 만든다. 핵심은 **만드는 것으로 끝이 아니라 각 함수가 맞는지 스스로 증명해야 한다**는 점이다.

| 문항 | 만들 것 | 무엇으로 맞다고 할 것인가 |
|---|---|---|
| 1-1 | `dot` · `norm` · `angle_between` | 손으로 계산한 값과 일치 |
| 1-2 | `normalize` | 영벡터를 넣어보고 그 결과를 근거로 처리 방식을 정함 |
| 1-3 | `project` · `reject` | 남는 성분이 수직인가, 두 성분을 더하면 원래 벡터인가 |
| 1-4 | `skew` · `cross` | `np.cross` 와 같은 값인가, 반대칭성이 성립하는가 |
| 1-5 | `plane_normal` | 세 점이 만드는 평면의 단위 법선 |
| 1-6 | `row_echelon` · `rank` · `det` | rank 가 왜 3 이 아닌지 설명하고 행렬식과 앞뒤가 맞는가 |

특히 **1-2 가 인상적이었다.** "영벡터를 넣으면 어떻게 되는지 **직접 실행해 기록한 뒤** 처리 방식을 정하라"고 되어 있다. 0으로 나누는 상황을 미리 막으라는 게 아니라, **터뜨려 보고 나서 결정하라**는 순서다. 예외 처리를 감으로 넣지 말라는 뜻으로 읽었다.

## 2. 규약이 과제의 절반이다

```
난수는 np.random.default_rng(42) 로 고정
수치 비교는 np.allclose / np.isclose
np.linalg 는 검산용으로만, 쓸 때마다 주석으로 검산임을 밝힌다
각 문항은 (1) 설명 마크다운 → (2) 코드 → (3) 검증 순서
```

**시드를 고정하는 이유**는 결과가 매번 달라지면 "내 구현이 틀린 건지 난수가 달라진 건지" 가릴 수 없기 때문이다.

**`==` 대신 `np.allclose` 를 쓰는 이유**는 부동소수점 때문이다. `cos(45°)` 같은 값은 이진수로 정확히 표현되지 않아서, 수학적으로 같아야 할 두 값이 마지막 자리에서 어긋난다. 지난주 회전행렬 검증에서 오차가 `1.8e-15` 로 나왔던 것과 같은 이유다.

**`np.linalg` 를 검산용으로만 쓰라는 제약**이 이 과제의 핵심이다. 답을 아는 도구를 옆에 두되 그것으로 풀지는 않는다. 내 구현과 대조해서 맞는지만 본다.

## 3. 행렬식의 부호는 행을 몇 번 바꿨는지로 정해진다

`det` 를 손으로 구현하려면 부호 규칙을 알아야 한다.

- 행을 **홀수 번** 교환했으면 **마이너스**
- **짝수 번**이면 **플러스**

행 교환이 부호를 뒤집는다는 성질이라, 소거 과정에서 몇 번 바꿨는지를 세어 두어야 마지막에 부호를 맞출 수 있다. `row_echelon` 을 만들 때 교환 횟수를 함께 반환하도록 설계해야 한다는 뜻이다.

## 4. 사이각을 구할 때 arccos

`angle_between` 은 내적에서 각을 꺼내는 함수다.

```math
\theta = \arccos\frac{a\cdot b}{\Vert a\Vert\,\Vert b\Vert}
```

`arccos` 가 곧 `cos⁻¹` 이고, 코드에서는 `np.arccos` 다. 여기서 조심할 게 하나 있다 — 부동소수점 오차로 분수 값이 `1.0000000002` 처럼 나오면 정의역을 벗어나 `nan` 이 된다. `np.clip(x, -1, 1)` 로 잘라주고 넣어야 안전할 것 같다.

## 5. rank 가 3 이 아닌 이유 — 1-6 이 노리는 것

주어진 세 벡터는 `(1,0,1)`, `(0,1,1)`, `(1,1,2)` 다. 눈으로 봐도 **세 번째가 앞의 둘을 더한 것**이다.

```
(1,0,1) + (0,1,1) = (1,1,2)
```

세 개가 있어도 독립된 방향은 둘뿐이라 rank 는 2 다. 그리고 이때 행렬식은 0 이 된다. **rank 와 det 가 서로 다른 말이 아니라 같은 사실의 두 표현**이라는 걸 확인하라는 문항으로 보인다.

## 7. 막혔던 지점 / 메모

- **`np.arccos` 는 정의역을 벗어나면 `nan` 을 낸다.** 내적을 노름 곱으로 나눈 값이 부동소수점 때문에 1 을 아주 조금 넘길 수 있다. `np.clip` 으로 감싸는 습관이 필요하다.

- **`normalize` 의 영벡터 처리**를 어떻게 할지 아직 못 정했다. 예외를 던질지, 영벡터를 그대로 돌려줄지, `nan` 을 낼지 — 과제가 "직접 실행해 보고 정하라"고 한 만큼 먼저 돌려보고 판단해야 한다.

- 외적을 **반대칭행렬 곱**으로 구현하라는 건 단순히 다른 방법을 써보라는 게 아니다. 벡터 연산을 행렬 연산으로 바꿔 두면 나중에 미분이나 합성을 그대로 적용할 수 있다. 지난주 회전행렬에서 본 흐름과 이어진다.

- 검증을 통과/실패로 찍어주는 헬퍼를 미리 만들어 두면 22 개 셀을 훑을 때 눈으로 확인하기 쉽다. `PASS` / `FAIL` 문자열을 붙여 출력하는 정도로 충분하다.

- 오후에는 `openarm_hardware` 쪽 자료(조립 STEP, 3D 프린트 STL, 배선도)도 훑어봤다. 지금 만드는 벡터 연산이 결국 저 팔의 자세를 계산하는 데 쓰인다고 생각하니 과제의 위치가 조금 더 분명해졌다.
