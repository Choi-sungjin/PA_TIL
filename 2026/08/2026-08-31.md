## 1. skew(a) — 외적을 행렬 곱으로 바꾸기

벡터 $a$ 로 만드는 반대칭 행렬부터 시작했다.

```math
[a]_\times = \begin{bmatrix} 0 & -a_3 & a_2 \\ a_3 & 0 & -a_1 \\ -a_2 & a_1 & 0 \end{bmatrix}
```

이걸 왜 만드냐면 **외적을 행렬 곱으로 바꿔주기 때문**이다.

```math
[k]_\times v = k \times v
```

외적은 두 벡터를 받는 연산이라 행렬 하나로 표현되는 다른 변환들과 섞어 쓰기가 불편한데, `skew` 를 거치면 그냥 행렬 곱이 된다. 각속도나 회전의 미분이 전부 $[\omega]_\times$ 꼴로 정리되는 이유가 이것이었다.

대각성분이 반드시 0인 것도 그냥 정의가 아니라 의미가 있다. $a \times a = 0$ 이니까 자기 자신과의 성분이 살아남을 수 없다.

## 2. 로드리게스 공식 — 축 하나와 각 하나로 회전행렬 만들기

8월 27일에 만든 건 $R_x, R_y, R_z$ 라 축이 좌표축일 때만 쓸 수 있었다. 로봇 관절은 비스듬한 축으로 돌기 때문에 **임의의 축 $k$ 를 중심으로 $\theta$ 만큼** 도는 행렬이 필요하다.

```math
R = I + \sin\theta\,[k]_\times + (1 - \cos\theta)\,[k]_\times^2
```

칠판에서 손으로 검산할 때 축을 $k = (0, 0, 1)$ 로 놓고 전개했다. 그러면 $[k]_\times$ 가 z축 스큐 행렬이 되고, 결과가 정확히 $R_z(\theta)$ 와 같아진다. **로드리게스가 축별 회전행렬의 일반화**라는 게 특수한 값을 넣어봤을 때 드러났다.

입력이 축 $k$ 와 각 $\theta$ 두 개뿐이라는 것도 짚고 넘어갔다. 회전축과 회전각만 있으면 3차원 회전이 하나로 정해진다 — 오일러각처럼 순서를 정해야 하는 문제가 없다.

`rotation.py` 의 공개 함수 목록이 오늘 배운 것의 목차 그대로였다.

```text
rot_x, rot_y, rot_z, rodrigues,
gram_schmidt, orthogonality_error, is_rotation,
axis_angle_from_matrix, quaternion_from_axis_angle
```

`from .vectors import det, normalize, skew` — 지난주 벡터 모듈을 그대로 가져다 쓴다. 과제가 층층이 쌓이는 구조였다.

## 3. 회전행렬은 오래 쓰면 썩는다

여기가 오늘 가장 인상 깊었던 부분이다. 수학적으로는 회전행렬끼리 아무리 곱해도 회전행렬이어야 한다. 그런데 실제로는 아니었다.

```text
매 스텝 0.001 rad 씩 도는 미소 회전을 10만 번 누적
R_step = rot_z(0.001) @ rot_y(0.0005) @ rot_x(-0.0007)
acc = acc @ R_step  를 반복
```

곱셈 한 번마다 부동소수점 상대오차가 $\varepsilon_{\mathrm{machine}}$ 수준으로 섞여 들어가고, 이게 랜덤워크처럼 쌓여서 **대략 $\sqrt{n}$ 에 비례해 커진다.** 오차가 그냥 $n$ 에 비례해 커지는 게 아니라는 게 포인트다. 부호가 제멋대로라 서로 상쇄되기도 하지만 완전히 없어지지는 않는다.

10만 번이 과장 같지만, 100 Hz IMU면 1000초, 17분이면 도달한다. 로봇이 몇 시간 돌면 자세 행렬이 조용히 회전행렬이 아니게 된다는 뜻이다.

## 4. 직교성을 숫자로 재기

"망가졌다"를 감이 아니라 값으로 봐야 고칠 수 있다. 회전행렬의 조건은 이거다.

```math
R^{\mathsf{T}} R = I
```

그래서 오차를 이렇게 정의했다.

```math
e(R) = \lVert R^{\mathsf{T}} R - I \rVert_F
```

프로베니우스 노름이라 성분 제곱합의 제곱근이다. 완전한 회전행렬이면 0이고, 누적할수록 이 값이 커진다. 1000번마다 `orthogonality_error(acc)` 를 기록해 그래프로 그리니 오차가 자라는 모양이 그대로 보였다.

행렬 하나를 스칼라 하나로 요약해서 추적 가능하게 만든 건데, 이 발상 자체가 쓸모 있어 보였다. "직교행렬인가?"는 참·거짓이라 언제 손봐야 할지 알 수 없지만, $e(R)$ 은 임계값을 걸 수 있다.

## 5. Gram-Schmidt 재직교화 — 지난주 연산이 다시 나온다

고치는 방법은 축마다 순서대로 처리하는 것이다.

```text
r₁ 정규화
r₂ 에서 r₁ 성분 제거 → 정규화
r₃ 에서 r₁, r₂ 성분 제거 → 정규화
```

목표는 세 열이 이 조건을 만족하게 만드는 것.

```math
\lVert r_1 \rVert = \lVert r_2 \rVert = \lVert r_3 \rVert = 1, \qquad r_1 \cdot r_2 = r_1 \cdot r_3 = r_2 \cdot r_3 = 0
```

**성분 제거가 결국 8월 26일에 만든 `project` / `reject` 였다.** 새 연산을 배운 게 아니라 지난주 것을 순서대로 세 번 부르는 거였다. 과제가 왜 벡터 모듈부터 시작했는지 여기서 이해됐다.

수치적으로는 **modified Gram-Schmidt** 를 쓴다. 원래 방식은 원본 벡터를 기준으로 모든 성분을 한꺼번에 빼는데, modified 는 **하나 뺄 때마다 즉시 갱신**해서 다음 계산이 이미 정리된 벡터를 쓴다. 수식으로는 같은 결과지만 부동소수점에서는 후자가 오차를 덜 물고 간다. 오차를 고치는 코드가 오차에 약하면 안 되니까 당연한 선택이었다.

## 6. pytest 로 회전행렬을 검증하기

`tests/test_rotation.py` 가 확인하는 건 네 가지였다.

| 확인할 것 | 테스트 |
| --- | --- |
| 열들이 서로 직교하는 단위벡터인가 | `test_columns_are_orthonormal` |
| 행렬식이 1인가 | `test_determinant_is_one` |
| 역행렬이 전치와 같은가 | `test_inverse_equals_transpose` |
| 재직교화 결과가 다시 직교행렬인가 | `test_gram_schmidt_restores_orthogonality` |

행렬식이 $1$ 이어야 한다는 조건이 중요하다. $-1$ 이면 직교행렬이긴 해도 반사가 섞인 것이라 회전이 아니다. 전치가 역행렬이라는 성질은 8월 27일에 정리해뒀던 건데, 그게 그대로 테스트 한 줄이 됐다.

각도를 `parametrize` 로 여러 개(0, $\pi/6$, $\pi/4$, $\pi/2$, 2.0, $\pi$, 음수까지) 넣고 세 축에 대해 돌리니 조합이 수십 개로 불어났다. 손으로 하나씩 확인할 수 없는 걸 테스트가 대신 훑어주는 게 이런 경우였다.

## 7. 일부러 버그를 심어 테스트를 시험하기

오늘 제일 새로웠던 부분. **테스트가 통과하는 것과 테스트가 쓸모 있는 것은 다르다.** 아무것도 검사하지 않는 테스트도 통과는 한다. 그래서 코드를 일부러 망가뜨려 보고 테스트가 빨간불을 내는지 확인했다.

`rot_z` 의 부호 하나만 뒤집는다.

```python
BUG_FROM = "return np.array([[c, -s, 0.0],"
BUG_TO   = "return np.array([[c,  s, 0.0],"   # 부호 뒤집기
assert original.count(BUG_FROM) == 1          # 치환 대상이 한 곳인지 먼저 확인
```

그리고 pytest 를 돌려 실패하는지 본다. 절차에서 배운 게 두 가지 있다.

- **치환 전에 `count == 1` 을 확인한다.** 같은 문자열이 여러 곳에 있으면 의도하지 않은 자리까지 바뀌어서, 뭘 시험한 건지 알 수 없게 된다.
- **`try` / `finally` 로 반드시 원본을 되돌린다.** 중간에 예외가 나도 `finally` 는 실행되므로 소스가 망가진 채로 남지 않는다. 8월 28일에 폴더를 옮기며 `복원.sh` 를 먼저 만들었던 것과 정확히 같은 습관이다.

## 9. 막혔던 지점 / 메모

- **오차가 $n$ 이 아니라 $\sqrt{n}$ 으로 쌓인다.** 매번 같은 방향으로 틀리는 게 아니라 랜덤워크라서다. 그래도 커지는 건 커지는 거라 주기적인 재직교화가 필요하다.
- **`det = 1` 과 `det = -1` 을 구분해야 한다.** 둘 다 직교행렬이지만 $-1$ 은 반사가 섞인 것이다. "직교행렬이면 회전행렬"이 아니다.
- **modified Gram-Schmidt 를 쓰는 이유는 수식이 달라서가 아니다.** 결과는 같고 부동소수점 거동만 다르다. 손으로 풀 때는 차이가 없어서 그냥 지나치기 쉽다.
- **테스트가 초록불이라고 검증된 게 아니다.** 코드를 망가뜨렸을 때 빨간불이 켜지는지까지 봐야 그 테스트를 믿을 수 있다.
- 소스를 고쳤다 되돌리는 코드는 `finally` 없이 쓰면 안 된다. 중간에 죽으면 망가진 소스가 그대로 남는다.
- 오늘 녹화가 화면만 잡히고 소리가 안 들어갔다. 다음부터 PicPick 설정에서 오디오 입력을 확인하고 시작할 것.
