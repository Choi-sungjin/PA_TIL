## 1. 환경 세팅과 빌드 사이클

파이썬은 인터프리터가 바로 실행해줬지만 C++은 컴파일러를 거쳐야 실행 파일이 나온다. 그래서 **작성 → 저장 → 빌드 → 실행**이 한 세트다.

VS Code에는 마이크로소프트 배지가 달린 C++ 확장을 설치했다. 자동완성과 실시간 오류 표시가 붙어서 타이핑량이 확 줄었다. 실제로 함수 위에 커서를 올리면 그 함수를 쓰기 위해 어떤 헤더가 필요한지까지 툴팁으로 뜬다 — 모르는 문법이 나오면 검색보다 이게 빨랐다.

컴파일은 `g++`로 한다.

```bash
g++ -std=c++17 -o hello hello.cpp   # -o 뒤가 만들어질 실행 파일 이름, 마지막이 소스 위치
./hello                             # 실행
```

`-std=c++17`의 17은 C++ 표준 버전이다. `-o hello`로 이름을 정해두면 이후엔 그냥 `./hello`로 바로 돈다.

### 저장 안 하면 빌드가 헛돈다

VS Code 탭에 **점(●)이 떠 있으면 저장 안 된 상태**다. 이 상태로 빌드하면 방금 고친 내용이 아니라 이전 파일이 컴파일된다. 코드는 고쳤는데 결과가 그대로라 한참 헤맬 수 있는 지점. 빌드 전 `Ctrl+S`는 습관으로 박아둬야 한다.

### Hello World 뜯어보기

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, World!" << std::endl;
    return 0;
}
```

파이썬이면 `print(...)` 한 줄인데 여기선 네다섯 줄이다. 각 줄의 이유:

| 조각 | 하는 일 |
|---|---|
| `#include <iostream>` | 터미널 표준 입출력 기능을 가져오는 헤더. `std::cout`을 쓰려면 필수 |
| `int main()` | 프로그램이 실제로 굴러가는 진입 함수 |
| `std::cout << ...` | 표준 출력으로 값을 흘려보냄. `<<`가 보낼 것들을 구분 |
| `std::endl` | 줄바꿈. 이걸 빼면 다음 출력이 같은 줄에 이어 붙는다 |
| `return 0` | 정상 종료를 뜻하는 반환값 |

`std::endl`을 안 붙이면 줄바꿈이 안 된다는 게 처음엔 실수처럼 보였는데, 배열을 콤마로 이어서 한 줄에 찍을 때는 오히려 이쪽이 편했다. 빠뜨린 게 아니라 **줄바꿈이 명시적인 것**이었다.

중괄호를 여는 위치(`int main() {` vs 다음 줄에 `{`)는 취향이라 둘 다 허용된다. 다만 함수가 어디서 시작하고 끝나는지 놓치면 오류가 나므로 한 방식을 정해서 일관되게 쓰는 게 낫다.

## 2. 타입 — 편의가 아니라 메모리 계약

파이썬은 동적 타입이라 타입을 안 적어도 됐다. C++은 직접 적어야 한다. 이유는 **타입을 적는 행위가 곧 메모리 공간을 얼마나 잡을지 정하는 것**이기 때문이다.

| 타입 | 크기 | 용도 |
|---|---|---|
| `short` | 2바이트 | 짧은 정수. 실제로는 거의 안 쓴다 |
| `int` | 4바이트 | 가장 흔한 정수 |
| `long` | 더 큼 | int로 모자랄 때 |
| `float` | 4바이트 | 실수 |
| `double` | 8바이트 | 더 긴 소수점을 담는 실수 |
| `bool` | — | 참/거짓만 |
| `char` | — | 문자 **한 개** |
| `std::string` | — | 긴 문자열 (`#include <string>` 필요) |

```cpp
int battery = 220;
long distance = 1500;
unsigned int age = 30;   // 음수를 받지 않겠다는 선언
double pi = 3.141592;
float ratio = 3.14f;     // 뒤의 f는 "이건 float"이라는 리터럴 표시
bool robot_state = true;
char sensor = 'A';
std::string name = "lidar_front";
```

`unsigned`는 음수를 안 쓰겠다는 표시다. DB의 id 컬럼이나 로봇 번호처럼 **음수가 논리적으로 존재할 수 없는 값**에 붙인다.

실수는 특별한 이유가 없으면 `double`을 쓰는 편이 낫다는 조언을 들었다. 센서 값이 소수점 몇 자리까지 들어올지 모르기 때문이다. 반대로 라즈베리파이처럼 자원이 빠듯한 보드에서는 필요한 만큼만 잡아야 한다 — 노트북에서는 신경 안 써도 되지만 로봇 PC나 임베디드에서는 타입을 빡빡하게 지정하는 게 정답.

### 타입 에러가 왜 나는지가 중요하다

```cpp
int readings[5] = {10, 20.04, 30, 13, 1};   // 컴파일 실패
```

`int` 배열에 소수점을 넣으면 아예 컴파일이 안 된다. 여기서 "타입이 달라서"라고만 이해하면 절반이다. **20.04를 담으려면 int로 잡아둔 메모리 크기로는 부족하기 때문**이다. 반대로 `double` 배열에 정수 10을 넣는 건 통과한다 — 내부적으로 10.0으로 취급되니까. 다만 이건 정수 하나를 8바이트 자리에 앉히는 셈이라 메모리는 낭비된다.

`sizeof`로 크기를 직접 찍어볼 수 있다.

```cpp
std::cout << "size is " << sizeof(value) << std::endl;
```

### 상수 — const와 constexpr

바뀌면 안 되는 값은 아예 못 바꾸게 선언한다.

```cpp
const double MAX_SPEED = 1.5;      // 실행 중에 결정될 수도 있는 상수
constexpr long ROBOT_ID = 7;       // 컴파일 시점에 이미 확정
```

둘의 차이는 **확정 시점**이다. `const`는 계산 도중에 정해질 수 있지만, `constexpr`은 컴파일하는 순간 값이 박힌다. IP나 로봇 ID처럼 절대 흔들리면 안 되는 값에 `constexpr`이 어울린다.

`auto`도 있다 — 컴파일러가 타입을 알아서 추론해준다. 다만 수업에서는 **쓰지 말라고** 못을 박았다. 타입을 직접 지정하는 게 이 언어를 쓰는 이유이기 때문.

### 스코프

```cpp
int number = 1;          // 함수 밖

int main() {
    {
        int number = 2;  // 이 블록 안에서만 2
    }
    // 여기서는 다시 1
}
```

중괄호가 하나의 스코프(블록)를 만든다. 이름이 같아도 블록 안팎은 **서로 다른 변수**다. 처음엔 둘 다 1이 나올 줄 알았는데 1과 2가 따로 나온다.

## 3. 연산자

### 사칙연산과 타입의 함정

```cpp
int a = 7, b = 3;        // 콤마로 한 번에 선언
std::cout << a / b << std::endl;   // 2 (2.33이 아니다)
```

`7 / 3`이 2로 나온다. 소수점이 버려지는 게 아니라 **int로 선언했으니 int 크기에 맞춰 잘리는 것**이다. 2.33333을 보려면 타입을 실수로 바꿔야 한다.

나머지 연산 `%`는 정수에만 쓸 수 있다. 실수의 나머지가 필요하면 `<cmath>`의 `fmod`를 써야 한다고 확장 툴팁이 알려줬다. 사칙연산 관련 함수를 쓰려면 `<cmath>`를 include해야 한다.

로봇 쪽에서 특히 새겨야 할 것: **π를 3.14로 넣는 순간 사고가 난다.** 최소 3.141592, 가능하면 소수점 자리를 넉넉히 넣거나 라디안으로 계산한다.

### 복합 대입 연산자

```cpp
int count = 100;
count += 50;   // 150
count -= 25;   // 125
count *= 2;    // 250
count /= 5;    // 50
```

`count += 50`은 "100에 50을 더한 값을 다시 count에 넣는다"는 뜻이다.

### 증감 연산자 — 전위와 후위

```cpp
int i = 5;
++i;   // 전위: 먼저 올리고 값을 반환
i++;   // 후위: 값을 먼저 내보내고 그 다음에 올림
```

`i++`와 `++i`는 결과적으로 i가 6이 되는 건 같지만, **그 시점에 반환되는 값이 다르다.** 후위는 원래 값이 먼저 나오고 나서 증가하고, 전위는 증가부터 하고 그 값을 돌려준다. 실행해보면 출력이 실제로 다르게 찍힌다.

관례상 **전위를 쓰는 게 기본**이다. 후위는 값이 언제 반영되는지 헷갈려서 버그를 만들기 쉽다. 주로 for문 반복에서 쓴다.

### 비교와 논리 연산자

```cpp
double battery_voltage = 12.0;
bool lidar_is_ok = true;
bool imu_is_ok = true;

std::cout << std::boolalpha;                    // true/false를 글자로 출력
std::cout << (battery_voltage < 50) << std::endl;
std::cout << ((lidar_is_ok && imu_is_ok) ? "OK" : "NOT OK") << std::endl;
```

- `<` `>` 미만/초과, `<=` `>=` 이하/이상
- `&&` (AND): **둘 다** 참이어야 참
- `||` (OR): **하나만** 참이어도 참. `\` 옆 키를 Shift와 함께 눌러 만든다 (소문자 l이 아니다)
- `!` (NOT): 값을 뒤집는다. `!true`는 0, `!false`는 1로 찍힌다

`std::boolalpha`를 안 쓰면 참/거짓이 1과 0으로 나온다.

## 4. 흐름 제어

### if / else if / else

```cpp
if (battery_level == 100) {
    std::cout << "FULL" << std::endl;
} else if (battery_level >= 50) {
    std::cout << "MID" << std::endl;
} else if (battery_level >= 0) {
    std::cout << "LOW" << std::endl;
} else {
    std::cout << "EMPTY" << std::endl;
}
```

여기서 가장 중요한 건 **위에서 아래로 읽힌다**는 점. battery_level이 100이면 사실 `>= 50`도 `>= 0`도 전부 참이다. 그런데 출력은 하나뿐이다. 먼저 걸리는 조건에서 끝나고 나머지는 아예 검사조차 안 되기 때문이다. 조건 순서를 잘못 잡으면 아래 조건은 영원히 실행되지 않는다.

`==`는 "같다"라는 비교다. `=`(대입)와 헷갈리기 쉽다.

### switch

값이 딱 떨어지는 하나일 때는 if를 길게 늘어놓는 대신 switch가 읽기 편하다.

```cpp
char lidar_code = 'F';

switch (lidar_code) {
    case 'F':
        std::cout << "FRONT" << std::endl;
        break;
    case 'B':
        std::cout << "BACK" << std::endl;
        break;
}
```

`break`는 switch 밖으로 빠져나오라는 뜻이다. 기능은 if와 같지만 **가독성**에서 유리하다.

### for문 — 두 가지 방식

```cpp
int readings[5] = {30, 13, 1, 20, 5};

// ① 인덱스로 도는 방식
for (int i = 0; i < 5; ++i) {
    std::cout << readings[i] << std::endl;
}

// ② 범위 기반
for (int value : readings) {
    std::cout << value << std::endl;
}
```

①은 "5"를 코드에 박아둔 것이고, ②는 **배열 길이만큼 알아서 돈다.** 배열 크기가 5에서 10으로 바뀌면 ①은 숫자를 같이 고쳐야 하지만 ②는 건드릴 게 없다. 파이썬의 `for x in list`와 같은 발상.

배열은 파이썬과 달리 **길이를 먼저 정해야** 하고 그 길이에 맞는 값을 넣어야 한다. 인덱스는 0부터 — 5개면 0,1,2,3,4다.

### while과 do-while

```cpp
int number = 0;
while (number < 5) {
    std::cout << number << std::endl;
    ++number;
}
```

`while(1)`은 항상 참이라 무한 루프가 된다. 조건을 하나만 잘못 잡아도 **다음 코드로 넘어가지 못하고 갇힌다.** 반대로 모터 구동처럼 계속 돌아야 하는 상황에서는 `while(1)`을 의도적으로 쓴다.

`break`로 빠져나올 때 순서를 조심해야 한다.

```cpp
while (1) {
    if (number >= 10) break;   // 조건이 출력보다 위에 있으면 10은 안 찍힌다
    std::cout << number << std::endl;
    ++number;
}
```

10에 도달한 순간 출력 없이 바로 탈출한다. 10까지 보고 싶으면 break 조건을 아래로 내리거나 탈출 직전에 출력을 한 번 더 넣어야 한다. **코드는 위에서 아래로 순서대로 읽는다**는 원칙이 여기서도 그대로다.

`do-while`은 조건 검사보다 **본문을 먼저 한 번 실행**한다. 순서가 반대인 셈.

단순 반복은 for문이 구조가 짧고 조건이 한 줄에 다 들어가서 더 편하다.

## 5. 함수와 입력

```cpp
int add(int a, int b) {
    return a + b;
}

int main() {
    int num1, num2;
    std::cout << "Enter two numbers: ";
    std::cin >> num1 >> num2;

    int sum = add(num1, num2);
    std::cout << sum << std::endl;
    return 0;
}
```

`std::cin`으로 터미널에서 값을 입력받는다. 출력이 `<<`라면 입력은 `>>` — 방향이 반대다.

함수를 정의할 때 괄호 안에 넣은 것들이 **인자**다. `add(a, b)`는 이 함수를 쓸 때 반드시 그 자리에 값을 채워야 한다는 뜻이고, `main()`은 인자가 없으니 그냥 실행되는 함수다.

### 계산 결과는 바로 출력하지 말고 변수에 담을 것

이날 반복해서 강조된 습관이다.

```cpp
std::cout << a + b << std::endl;   // 이러지 말 것

int c = a + b;                     // 이렇게
std::cout << c << std::endl;
```

아무리 간단한 계산이라도 결과를 변수에 저장한 뒤 출력한다. 계산과 출력을 분리해야 나중에 그 값을 재사용하거나 검증할 수 있다.

## 6. 메모리 모델 — 스택과 힙

C++을 배우면서 가장 어렵다고 하는 지점. 그리고 앞의 모든 타입 이야기가 결국 여기로 모인다.

파이썬은 메모리를 알아서 관리해줬지만 C++은 **직접 제어**한다. 쓸 건지, 얼마나 쓸 건지, 언제 쓸 건지를 내가 정한다. 잘못 관리하면 필요 없는 메모리가 계속 붙잡혀 있는 **메모리 누수**가 생기고, 다른 기능이 돌지 못하거나 프로그램이 죽는다.

```
스택(stack)                          힙(heap)
지역 변수 영역                        동적 할당 영역
선언한 대로 쓰이고 사라짐              실행 중에 크기를 할당
크기가 미리 정해져 있음                필요할 때 잡고, 직접 해제해야 함
```

지금까지 `int battery = 220;` 같은 걸 쓴 게 전부 스택에 영역을 잡은 것이다. **용어가 낯설 뿐 이미 계속 하고 있던 일**이라는 설명이 이해에 도움이 됐다.

### new와 delete

```cpp
Motor* motor = new Motor();   // 힙에 할당
// ... 사용 ...
delete motor;                 // 반드시 해제
```

`new`로 만들었으면 `delete`로 꺼야 한다. 안 끄면 그 메모리는 쓰지도 않으면서 계속 붙잡혀 있는 상태가 된다. 실행 로그를 보면 delete 시점에 소멸자가 호출되고 인스턴스가 사라지는 게 순서대로 찍힌다.

클래스에서 `~ClassName()`(물결 표시)이 소멸자로, 메모리를 해제할 때 불린다.

"작은 값인데 이걸 꼭 해야 하나?" 싶지만 — 라이다 센서 한 번 스캔이 적게는 수백 KB, 많게는 2MB다. 이게 해제 없이 계속 쌓인다고 생각하면 답이 나온다. 노트북은 32GB라 버티지만 로봇에 올리면 이야기가 다르다.

### 스마트 포인터

포인터를 직접 관리하는 게 복잡하고 위험해서, 비교적 최신 C++에는 **스마트 포인터**가 있다. 소유자가 없어지면 자동으로 해제되므로 `delete`를 잊어도 누수가 안 난다. ROS2에서는 `rclcpp` 라이브러리를 통해 기본적으로 이 방식을 쓴다고 한다.

### std::vector

STL 컨테이너 중 로봇 코드에서 가장 많이 쓰이는 것. 파이썬의 리스트에 해당하고, 성격은 **numpy의 배열에 가깝다.**

핵심은 **연속된 메모리에 저장된다**는 점 — 그래서 캐시 효율이 좋다. numpy를 쓰는 이유가 메모리 배치 때문이었던 것과 같은 논리다. 실제로 카토그래퍼(구글이 만든 지도 작성 라이브러리) 코드를 열어보니 라이다 값을 다루는 부분에 벡터가 쓰이고 있었다.

STL은 검증된 자료구조·알고리즘 모음이고, 파이썬에서 쓰던 것들과 이렇게 대응된다.

| 파이썬 | C++ (STL) |
|---|---|
| list | `std::vector` |
| dict | `std::map` |
| set | `std::set` |
| tuple | `std::tuple` |
| str | `std::string` |

시간 복잡도 개념도 그대로 따라온다. 이중 for문으로 정렬하면 제곱으로 늘어나는 것과 같은 이야기.

## 8. 막혔던 지점 / 메모

- **저장 안 하고 빌드**가 오늘의 1등 함정. 탭의 점(●)을 확인하는 습관. 없는 파일을 빌드하는 셈이 된다.
- `7 / 3`이 2로 나오는 것 — 버그가 아니라 int 타입의 정상 동작. 결과 타입을 실수로 바꿔야 한다.
- `||`는 소문자 L이 아니라 `\` 키를 Shift와 함께 누른 것. 눈으로는 구별이 잘 안 된다.
- **조건문·반복문은 위에서 아래로 읽힌다.** if 순서를 잘못 잡으면 아래 분기가 죽고, while에서 break 위치를 잘못 잡으면 마지막 값이 안 찍힌다.
- `std::endl`을 빼면 줄바꿈이 안 되는 게 아니라, **줄바꿈을 명시하는 게 원칙**이다.
- `auto`는 되긴 하지만 쓰지 말 것 — 타입을 직접 지정하는 게 C++을 쓰는 이유.
- 후위 증감(`i++`)보다 전위(`++i`)를 쓰는 게 관례. 값이 언제 반영되는지 헷갈리지 않게.
- `while(1)`은 무한 루프. 모터 제어처럼 계속 돌아야 할 때만 의도적으로 쓴다.
- `std::` 접두사는 표준 라이브러리를 뜻한다. 외부 라이브러리는 `#include "src/..."` 식으로 경로를 적어야 하고, 표준 라이브러리는 `<>`로 가져온다.
- 과제 전에 **코드 추상화**를 먼저 할 것. 어떤 기능이 필요하고 어떤 조건으로 나뉘는지를 종이나 메모장에 적고 나서 코드를 친다. 계산기라면 어떤 예외 처리가 필요한지(타입이 안 맞는 입력, 성립하지 않는 계산식, 값을 하나만 넣은 경우 등)를 먼저 나열해야 한다.
