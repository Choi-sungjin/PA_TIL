## 1. 폴더 구조를 먼저 정하고 시작한다

노트북 한 파일에 계산과 그림을 다 넣으면 당장은 빠르지만, 같은 계산을 스크립트로도 돌리려는 순간 복사·붙여넣기가 시작된다. 그래서 계산과 실행을 갈랐다.

```
SungjinChoi/
├── src/
│   ├── lidar.py          # 필터링·좌표변환·위험판정·회전 — 계산만
│   └── viz.py            # 그림만
├── notebooks/
│   └── 06_numpy.ipynb    # 설명과 실행 결과
├── 06_numpy.py           # 주피터 없이 돌리는 실행 스크립트
├── requirements.txt
├── .gitignore
└── README.md
```

`src/`에는 **계산만** 두고, 노트북과 스크립트는 그걸 불러다 쓰기만 한다. 같은 결과를 두 경로로 얻을 수 있고, 계산을 고치면 양쪽에 한 번에 반영된다.

### 모듈을 불러오려면 경로를 알려줘야 한다

`src/`는 파이썬이 기본으로 찾는 위치가 아니라서 그냥 `import lidar` 하면 실패한다.

```python
from pathlib import Path
import sys

ROOT = Path(__file__).resolve().parent
sys.path.append(str(ROOT / 'src'))

import lidar   # 이제 된다
```

`Path(__file__).resolve().parent`로 **스크립트 자신의 위치**를 기준 삼는 게 핵심이다. 현재 작업 디렉터리를 기준으로 하면 어디서 실행하느냐에 따라 깨진다.

노트북은 위치가 달라서 `sys.path.append('../src')`를 쓴다. 대신 `notebooks/`를 작업 디렉터리로 두고 실행해야 한다.

## 2. `.gitignore`를 커밋보다 먼저 만든다

순서가 중요하다. `git add .`를 먼저 해버리면 `__pycache__`나 `.venv/`가 한 번 추적 대상이 되고, 그 뒤에 `.gitignore`에 적어도 이미 들어간 파일은 계속 따라다닌다.

이번에 넣은 것:

```gitignore
.venv/                  # 가상환경 — requirements.txt 로 재현하므로 커밋 불필요
__pycache__/            # 파이썬이 자동 생성하는 캐시
*.py[cod]
.ipynb_checkpoints/     # 주피터 자동 저장본
.vscode/                # 에디터 설정 — 사람마다 다름
sim_lidar.png           # 스크립트가 만들어내는 결과물
```

기준은 **"다시 만들 수 있는가"** 다. 캐시·가상환경·결과 그림은 코드만 있으면 다시 생기니 넣지 않는다. 반대로 `requirements.txt`는 재현에 필요하므로 반드시 커밋한다.

제대로 걸렸는지는 이렇게 확인했다.

```bash
git ls-files | grep pycache    # 아무것도 안 나오면 성공
```

## 3. 저장소를 만들어 올리는 순서

```bash
cd ~/SungjinChoi
git init
git add .
git commit -m "first commit: 6강 NumPy 벡터 연산 실습"
git remote add origin git@github.com:SpartaPA/SungjinChoi.git
git branch -M main
git push -u origin main
```

`git branch -M main`은 기본 브랜치 이름을 `main`으로 바꾸는 것이다. `git init`이 `master`로 만드는 환경이 아직 있는데, GitHub 기본값은 `main`이라 안 맞추면 브랜치가 둘로 갈린다.

`-u`는 `--set-upstream`의 줄임이다. 한 번 걸어두면 다음부터는 `git push`만 쳐도 어디로 보낼지 안다.

### VS Code에서 하면

터미널을 안 쓰고도 된다.

| 단계 | 위치 |
|---|---|
| 저장소 만들기 | 좌측 **Source Control** 아이콘 → `Initialize Repository` |
| 변경 확인 | Changes 목록에서 파일 클릭 → diff가 좌우로 열림 |
| 스테이징 | 파일 옆 `+` (전체는 Changes 헤더의 `+`) |
| 커밋 | 메시지 입력 후 `Ctrl+Enter` |
| 올리기 | `Publish Branch` 또는 `... → Push` |

다만 **처음 한 번은 터미널이 편하다.** 원격 주소를 붙이고 브랜치 이름을 맞추는 건 GUI에서 오히려 단계가 많다. 올려둔 다음부터는 VS Code 쪽이 빠르다 — 변경된 줄이 색으로 보이고, 커밋 전에 diff를 눈으로 확인할 수 있다.

### SSH vs HTTPS

주소를 `git@github.com:...` 형태로 썼다. HTTPS(`https://github.com/...`)는 push할 때마다 토큰을 요구하고 만료되면 다시 발급받아야 한다. SSH 키를 한 번 등록해두면 그 뒤로는 묻지 않는다.

```bash
ssh -T git@github.com     # Hi <아이디>! 가 나오면 인증된 것
```

## 4. 반복문을 지우는 게 NumPy의 핵심이었다

가상 LiDAR 스캔 360개를 for 문 없이 처리했다.

### 마스크 — 조건을 배열째로 계산한다

```python
def valid_mask(scan, r_min=0.1, r_max=10.0):
    scan = np.asarray(scan)
    return (scan > r_min) & (scan < r_max)
```

`scan > r_min`이 숫자 하나가 아니라 **불리언 배열**을 돌려준다는 게 출발점이다. 그걸 `&`로 엮으면 조건 두 개를 동시에 적용한 마스크가 나온다. 걸러내기는 `scan[mask]` 한 줄.

주의할 점 — 파이썬의 `and`가 아니라 `&`를 써야 한다. `and`는 배열 하나를 통째로 참/거짓으로 바꾸려다 오류를 낸다.

결과: 360개 중 **284개 유효 (79%)**.

### 극좌표 → 직교좌표

```python
def polar_to_xy(r, theta):
    return np.column_stack([r * np.cos(theta), r * np.sin(theta)])
```

`np.cos(theta)`가 배열 전체에 한 번에 적용된다. `column_stack`으로 x, y를 열로 세우면 `(284, 2)` 점군이 된다.

### 회전은 행렬곱

```python
def rot2d(deg):
    th = np.radians(deg)
    c, s = np.cos(th), np.sin(th)
    return np.array([[c, -s],
                     [s,  c]])

def rotate(xy, deg):
    return np.asarray(xy) @ rot2d(deg).T
```

여기서 `.T`(전치)를 왜 붙이는지 한참 봤다. 교과서의 회전 공식은 점이 **열벡터**일 때 `R @ v` 지만, 우리 점군은 한 행이 한 점인 `(N, 2)` 모양이다. 행 기준으로 계산하려면 `xy @ R.T`가 되어야 한다.

회전은 원점까지 거리를 바꾸지 않으므로, 회전 전후 거리를 비교하면 검증이 된다.

```
45도 회전 전후 최대 차이: 1.8e-15
```

0이 아니라 `1.8e-15`인 게 정상이다. 부동소수점은 `cos(45°)` 같은 값을 정확히 담지 못한다. 그래서 `==`가 아니라 `np.allclose`로 비교해야 한다.

### 얼마나 빨라지나

```python
t_loop = timeit.timeit(lambda: lidar.loop_filter(scan), number=2000) / 2000
t_vec  = timeit.timeit(lambda: scan[lidar.valid_mask(scan)], number=2000) / 2000
```

```
for 문 19.9 us / 벡터화 1.28 us → 약 16배
```

같은 결과인데 16배 차이가 난다. 원소마다 파이썬 인터프리터가 개입하느냐, C로 짜인 반복이 한 번에 도느냐의 차이다. 360개에서 16배면, 라이다가 초당 수십 번 도는 실제 로봇에서는 이게 곧 제어 주기를 지키느냐 마느냐가 된다.

## 5. 전방 판정은 각도가 0에서 끊긴다

전방 ±30°를 고르는 마스크에서 걸렸다.

```python
def front_mask(theta, half_angle=np.pi/6):
    return (theta < half_angle) | (theta > 2*np.pi - half_angle)
```

각도가 0~2π 범위라 **전방 구간이 0 근처와 2π 근처 두 조각으로 갈린다.** 처음엔 `-30 < theta < 30`처럼 한 줄로 쓰려다 아무것도 안 잡혔다. 두 조건을 `|`(OR)로 이어야 한다.

전방이면서 1.5m 이내면 정지:

```python
danger = front_mask(theta) & (r < stop_dist)
```

결과는 위험 8개 → **정지**.

## 7. 막혔던 지점 / 메모

- **`requirements.txt`를 `pip freeze`로 만든 게 실수였다.** 시스템 파이썬에 깔린 ROS2 패키지까지 200개 넘게 들어갔다. `rclpy`, `rqt-*`, `ament-*`는 이 과제와 아무 상관이 없고, 다른 PC에서 `pip install -r requirements.txt`를 하면 pip로는 설치되지 않아 실패한다. 실제로 필요한 건 `numpy`, `matplotlib` 두 개뿐이다. 다음엔 `.venv`를 만들고 그 안에서 `pip freeze`를 해야 한다.

- **`matplotlib.use('Agg')`를 import보다 먼저 호출해야 한다.** 화면 없이 PNG로만 저장할 때 필요한데, `pyplot`을 먼저 import하면 백엔드가 이미 정해져 버려서 소용이 없다.

- `git add .`를 치기 전에 `git status`로 뭐가 잡히는지 먼저 본다. `.gitignore`가 제대로 걸렸는지 이때 드러난다.

- 커밋 메시지에 `first commit`이라고만 쓰지 말고 무엇을 넣었는지 붙이는 게 낫다. `first commit: 6강 NumPy 벡터 연산 실습`처럼 쓰면 나중에 `git log --oneline`만 봐도 파악된다.

- 축 비율을 안 맞추면 점군 그림에서 거리가 왜곡돼 보인다. `ax.set_aspect('equal')` 한 줄이 필요하다.
